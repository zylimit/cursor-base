**漏项建议器（init --suggest 一类）**
- 逐类问「用户有意不要这一项时怎么压住」，再真造配置跑一遍：目录类走 walk 吃 ignore，文件类用 existsSync 直查就绕过 ignore——文档说「写进 ignore 就不再报」只对前一类成立，后一类每次提交一条、压不住。
- 对表文档里写明的「不要就写 null / 空数组」：那正是建议器会报成漏项的状态；再看流程文字是不是写「报的漏项填进去再开工」——Agent 照做就把用户的取舍改回去了。
- 钩子里顺带跑的子步骤，挂住 / 非 JSON / 形状不对 / 抛错 / 旧版生成器 / 配置写坏六种本仓这期全攻不动（3 秒封顶、rc 0），预算优先花在噪声与流程文字上。
- 走文件的耗时：6 万文件 0.19 秒，别再造大目录测慢。

**指纹切片改了**
- 用 `git archive <基线> .claude/scripts | tar -x` 拿旧版生成器写说明、新版 check：来源不动也变「待更新」= 每个下游升级后一次性全体过期。再看验收规则是不是「check 全局 0 条」而职责是「只管这次改到的」——两条在升级后第一单就互卡。

**默认开启的流程文字**
- 主控 / 文件结构里的「（可选）」、自动触发行里有没有「用户明说不出」的判据，逐处对。
- 「Phase 收尾归位所有未分组」与「存量补齐只在用户要时做」这类全量 vs 增量的口子，搜同一动作在几处的范围词。
- 验收命令看不见的义务（没写说明不算不一致）：验收只跑 check 就验不到「新表写了说明」，问清谁、用哪条命令验。
