2026-11-23 审人读版需求规格（第二期）时每条都真复现过：

- **两边共用的隐去规则 = 核对器的盲区**：口令规则的值取到「空白为止」，套到中文散文上一口吞到下一个空格；比对「按隐去后的文字比」，吞掉的两边一样，check 0 条。造 `token:` / `password=` 后接一长串无空格中文的条目必中。
- **还原自检只证明「字落进了块或 lay」**：逐个列 lay 里存了什么，凡不是纯空白 / 纯结构记号的（围栏的 info string）都是「自检过了、页面上没有」的洞。
- **核对只比线性文字序列**：拿出页面代码的副本做突变（拍平列表树、标题全改 h6、章节多切一刀、打印副本清空），check 与测试多半全绿——结构、分页、打印副本没人管。
- **LCS 设上限的退化路径**：超上限后若不按位置配，所有块被报成「先后不对」。造 2100 块、首尾各改一字，2098 条假报。
- **fail-closed 自检要做删除突变**：把还原自检那一行注释掉、把 build 落盘前那一项删掉，跑两套测试看还绿不绿（这次全绿 = 零覆盖）。
- 出页面与核对各写一份去记号规则：20 万条随机串差分对拍，零相左才算两份对齐；别只读代码。

**Why:** 读者拿页面当来源的替身，这几类在真数据上 check 都报 0。
**How to apply:** 先做差分对拍与随机文档端到端（误报），再做渲染器副本突变与测试突变（假绿），最后才逐条对契约。scratchpad 可能是和别的会话共用的，清理只删自己建的那个子目录，绝不用 `c*` 这类通配。相关：[[pattern-ddl-facts-and-page-redaction]] [[handrolled-parser-needs-differential]]
