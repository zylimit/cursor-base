2026-11-22 审 plan-archive / progress-archive P-1 时三招都打中：

- **指针行被下游闸整行读 = 标题文字混进判据**：搬迁脚本只把 Task 行的编号写进指针后缀，但 lint 读指针时整行 findall，标题里的「REQ-X（推到下期）」也算已安排 → 范围外的被搬红、没人做的被搬绿。造法：✅ 标题带一个只在范围外声明的编号；真数据用「保留线改 0」的变异副本把能搬的全搬，搬前搬后对拍 lint 报错集合（OFR 撞出一条「没人做」消失）。同一份指针还被状态脚本读，一起对拍。
- **按「紧跟 + 更深 = 子项」认条目必攻插入**：往老写法（四空格）独立条目块的顶上插一条顶格新条目、不隔空行，整块被吞成它的子项，`--check` 从 56 条变 1 条、搬出 0，归档静默停摆。下游 recorder 换写法是真事，先查真数据有没有「顶格压在缩进块上」的先例。
- **测试牙用变异副本**：套件吃 `$1` 当被测脚本路径时，把变异写进 mktemp 副本直接喂；测试里写死的第二个脚本（如 LINT=）就拷测试改那一行，但 REPO_ROOT 由测试自身路径推，拷走后要显式传 `$1`。变异锚点替换没命中要报错，免得白跑出假绿。

- **「原因取子进程 stderr 首行」必被前置告警占位**：子进程在致命错误之前先往 stderr 打告警（Pinned 超封顶），首行就成了告警，真原因被藏。造法：告警条件与致命条件同时成立。
- **「改按编号 / 按日期排」的修复要看夹具是否与位置同序**：夹具编号与文档位置同序时，把排序删掉测试照绿（2026-11-22 plan-archive 复核实测），修复没被锁。

**How to apply:** 凡是「A 留指针、B 读指针」先对表 A 写的字段和 B 读的范围；凡是按缩进认结构，先造「浅压深、不隔空行」。见 [[pattern-archive-move-scripts]]、[[pattern_gate-scripts-false-green-in-machine-channel]]。
