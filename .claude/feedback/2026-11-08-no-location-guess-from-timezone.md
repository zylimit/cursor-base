# 机器所在地不从时区、用户名推；合规判断用到所在地先问

**问题描述**：2026-11-08 用户说「获取最新代码」，主 Agent 拉代码后发现最新提交 4d06dea「Add POI data」把五份真台账推上了公开 GitHub 仓库。主 Agent 凭几条间接线索——git 提交与 fra 的 +0800 时区、工号式用户名、全局 CLAUDE.md 里写给 Windows 工作电脑的内网代理配置——推断本机在欧洲以外，在给用户的决策题里写「这和 progress 里置顶的『真台账不进 Git、不出欧洲』冲突，我刚才拉代码时也把它们带到了本机」，选项里又写「本机保留五份台账……这等于放宽了『不出欧洲』」，把本机持有台账当成违反驻留约束来陈述。用户纠正原话：「我就就在法国」；「我虽然是新加坡时区，但是本机在法国境内」。

**触发场景**：发现数据驻留类问题、要判断数据出没出境时；手上只有时区、用户名、公司、网络配置这类间接线索，项目里只记了 fra 在法兰克福，没记本机在哪。时区设成新加坡、人和机器在法国，这类线索会直接把判断带反。

**教训/建议**：
1. 机器或人的物理所在地、所属法域，不从时区、用户名、公司、网络配置推——这些和所在地没有必然关系，本例时区是新加坡、机器在法国。
2. 合规判断要用到所在地时：用户确认过或项目文件写明的，引用并注出处；没记过的，先问一句「本机在哪个国家」，或在陈述里明标「推断：……，依据是……」，不写进给用户的事实陈述。
3. 决策题的选项描述只放核实过的事实与代价；推断出来的「违规」不当选项前提——本例选项里「这等于放宽了『不出欧洲』」就是把推断写进了选项。
4. 本条是 CLAUDE.md [角色]「四种话永远分开说」与「推断不进交付物，最多口头说依据」的一个实例；新增的只有一点：所在地、法域这类事实特别容易被间接线索带偏，用到就问。

**适用范围与例外**：适用于涉及数据驻留、合规、所在地或法域判断的场景：向用户陈述数据是否出境、出处置决策题、在 progress.md 或交接文档里写合规事实。用户确认过或项目文件已写明的位置（如 auto memory 记的「生产在法兰克福 ssh fra」）照用并注出处；其它例外未说明。
