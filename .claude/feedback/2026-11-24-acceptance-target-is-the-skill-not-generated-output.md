# 做完一项能力，验收的是技能，不是拿某个项目验出来的文档

**问题描述**：主 Agent 在框架仓里给「人读文档」加能力，做了三期（数据库设计、人读版需求规格、架构设计），验证一直拿同一个下游项目做。用户问「框架应该开发差不多了吧？」，主 Agent 按文档种类数进度（需求 11 条做完 6 条半、剩 4 条半），又讲了下游那套文档的内容状态，并建议第四期再做哪几份文档。用户纠正，原话：「我在乎的不是生成的文档，是你的skill」。主 Agent 随即拷了另一个下游项目的副本，打算自己再起一轮验证，被用户打断，原话：「你是做框架的，我让你生成文档，是验证你的SKill，你主要是做框架」。

**触发场景**：用户问「做得差不多了吗」这类收口性问题。主 Agent 把进度等同于「能生成多少种文档」，答的是产物，用户问的是技能。

**事后盘点（主 Agent 当场查的事实）**：
- 技能目录只有一份 68 行的 SKILL.md；同仓别的技能都带参考与范例（product-spec-builder 13 个附带文件、arch-designer 5 个、design-brief-builder 12 个）。
- `.claude/tests/cases/` 里没有该技能的真触发用例（只有 bug-fixer 与 product-spec 两条）。
- 技能里「小样」「截图」「升级」各 0 处；提模块划分、分批派 Sub-Agent 写说明、亲眼看页面、先出小样再铺开，这些做法只存在于这次会话的派单与临时目录里，没写进技能。
- 引擎有十四套契约测试 279 条，技能本身从没有新实例照着跑过。

**根因（框架侧）**：做完一项能力时，流程里没有哪一步要求「让没参与的新实例照技能跑一遍」。主 Agent 把自己会做当成了技能能用——会话里的做法在主 Agent 脑子里，不在技能里，而验收只看了引擎测试与下游产物。

**教训/建议**：
- 用户原话两句：在乎的是 skill，不是生成的文档；让主 Agent 生成文档是为了验证 skill，主 Agent 主要是做框架。以下是主 Agent 的理解，不是用户逐条说的：在下游出文档是用户发起的验证，主 Agent 该做的是把验证里暴露的问题写回技能；再验一次拿哪个项目、什么时候做由用户定，主 Agent 不自己另起。
- 判断一项带技能的能力「做到哪了」，数技能能不能被新实例独立用起来（做法是否写进技能、有无触发用例、有无新实例试跑），不数产物种类。
- 方向（只是方向，本条不改任何规则文件）：这一步或许该进 `skill-builder` 的收尾，或 dev-builder 的 Phase 收尾，作为「能力验收」的一条——由用户或主 Agent 决定要不要落。

**适用范围与例外**：框架仓里「技能 + 生成器 / 脚本 + 规则」成套的能力开发，收口、汇报进度、规划下一期时按这条来。用户明确只要某个项目的产物时不按；其它例外未说明。

**本次落地**：progress.md Decisions 已加 2026-11-24 一条，断点「下一步」改为把验证里暴露的问题写回技能；用户记忆已存一条；主 Agent 拷的另一个项目的临时副本已删。readable-docs 技能本体、skill-builder、dev-builder 均未改——补技能是后续动作，尚未做。
