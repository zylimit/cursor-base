# 选项里夹带自己的推论，复述举例又没讲清

**问题描述**：用户圈出看板「模板 · T0」列说「不要说用什么模板，要按照POI里面的类型来」，并在选项中选了「连排程一起改」。该选项文字是 AI 写的：「不再自动判 Massive，Massive 只能人工指定」。AI 据此把 Spec 改成「Massive 只人工指定」，复述时说 CHATILLON LA PALUD 会按 Transportation 排、搬迁活动消失。用户先问：「你说的是啥啊CHATILLON LA PALUD？」，解释后纠正：「CHATILLON LA PALUD 这个是有搬迁的，要用 Massive+Transportation并集」；追问 x 时答「x不用管，只关注 Total Avg. Weight」。

**触发场景**：用户要的是「排程跟 POI 类型走」这个方向；AI 把「取消自动 Massive」这个自己推出来的副作用写进选项描述，用户选的是方向，AI 却当成他认可了推论。复述时只抛站点名，没说是截图第几行、哪一列、从什么变成什么，用户无从核对，错误推论拖到第二轮才暴露。

**教训/建议**：
- 选项描述只写用户可判断的方向本身；AI 推出的副作用（取消自动判定、某类记录行为改变等）单列成一个独立问题让用户确认，不打包进选项。
- 复述影响时，引用实例要带定位：截图第几行、哪一列、变更前后各是什么；只给站点名等于没复述。
- 用户选「按类型来」后，对「类型 -> 模板」的映射，先拿几个真实例子（含 Transportation 有搬迁、Distribution、无类别）让用户核对，再写 Spec。
- 实际口径：模板跟 POI 类型走；Transportation 有搬迁户数要并上 Massive；x 不算搬迁，只看 Total Avg. Weight；只有 Distribution 不加 Massive；无类别不排程。

**正向确认（2026-11-10，用户确认有效的做法）**：
- 经过：用户在看板把 CHATILLON LA PALUD #1 的 Retassage-SR 从完成改回未完成，顶上 Retassage · done / planned 卡仍是 391 / 391，问「相关计划和完成数据是不变的吗？」。主 Agent 先读代码讲清现状（完成量来自 Operation，卡片按计划开始 ≤ 今天计入，与格子状态无关），并指出一处缺口：完成改回进行中时实际完成日不清空。用户答「开始执行的计划和执行了多少，需要根据那两个字段状态触发」，AskUserQuestion 两题（哪种状态算开始；改回进行中清不清实际完成日）都带推荐，用户选了推荐。
- 用户接着说「你的理解能力很强，点赞」，又补「就是要通过，两个阶段开始和完成，控制上面的计划量和完成量」。这句有两种读法、写出的代码不同：开始只管计划量、完成才管完成量；或开始后两个量一起算。主 Agent 没有按刚选的选项直接开工，而是拿用户刚改过的那个真实站点，算出两种读法下卡片各显示多少：「216 / 391（推荐，贴你的原话）」对「391 / 391」。用户选了 216 / 391。
- 做法：用户的追加说明能读出两种意思、且会改变代码时，不按上一轮选项闷头做；用用户刚操作过的真实对象，把每种读法下界面上的具体数字算出来让用户挑；推荐项贴用户原话字面。用户对这种问法明确点赞。
- 与上文关系：上文是「复述不带定位被追问」的反面教训，这里是同一条原则做对的样子，定位落到「用户刚操作的那一行 + 界面上会出现的数字」，用户一眼能核对。与 recommend-follows-literal-hard-constraint.md 一致（推荐项贴字面）。
- 本次落地：这是已发生的做法，当前产物（代码按 216 / 391 口径）由主 Agent 另行落地，此处只记录；skill / rule 本体未动。

**适用范围与例外**：同 frontmatter。选项由用户自己提出、不含 AI 推论时不适用。正向做法的适用面：用户追加说明有歧义且两种读法对应不同代码；有真实对象可算数字。歧义不改变代码、或算数字成本远高于一次提问时，不必这样做。
