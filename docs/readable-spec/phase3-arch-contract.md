# 人读文档 · 第三期契约：架构设计

需求见 Product-Spec.md（REQ-DOC-002，以及 REQ-DOC-005 里「模块连到表」的那一半），架构见 Architecture-Design.md。本文件是第三期各 Task 的行为契约，测试的断言只从这里推导。入口、退出码、配置文件、说明的落盘与指纹、原子落盘、隐去、核对的总体做法都与第一期相同（见 phase1-db-contract.md），这里只写新增的。

这一份文档回答接手的人第二步要问的话：**这个系统由哪几块组成、每一块管什么、块与块之间谁用谁、每一块对外提供什么、碰哪些表**。能从代码里机械取出来的（文件、引用、接口、读写的表）一律取出来；机械取不出来的只有两样——文件怎么归成模块（项目判断）、每个模块管什么（AI 写的说明）——页面上分得开。

下游一个项目的后端实数（2026-11-23）：非测试的 Python 文件 371 个（服务端 336 个、约 6.9 万行，另有工具脚本 35 个），其中 165 个平铺在同一个目录下；文件之间的引用 1058 条，像内部引用却解析不到的 2 条；服务端那 336 个文件里 332 个开头有一段说明，中位 191 个字；接口 226 个，分在 60 个文件里，其中 94 个的处理函数带说明；接口路径的前缀只有 1 处不是写死的。前端 484 个 TypeScript 文件，引用全是相对路径。

## A. 配置与项目判断

`config.json` 沿用 `codeRoots` 与 `ignore`，新增一项可选的：

- `archDocs`：现有的架构文档与决策记录的路径（相对项目根，可以多份）。`init` 在根目录有 `Architecture-Design.md` 时填上它；没有就是空数组。写了路径而文件不存在，退出码 2 并点名。

`map.json` 新增两项，人和 AI 都可以直接编辑，`status` 的规矩与表的分组相同（AI 只许写 `proposed`，`confirmed` 只由人改）：

```json
{
  "layers": ["界面", "接口", "业务", "数据", "工具"],
  "modules": [
    { "id": "ingest", "title": "基线导入", "layer": "业务",
      "paths": ["app/api/import_*.py", "app/api/ingest/**"], "status": "proposed" }
  ]
}
```

- `modules`：一个模块是一组文件。`paths` 是通配写法，与 `ignore` 同一套（`*` 不跨目录、`**` 跨目录）。`id` 只许小写字母、数字与连字符，页面地址由它推出。模块的先后就是页面上的阅读顺序。
- `layers`：从上到下的层名，可以没有。有它时每个模块的 `layer` 必须是其中一个；没有它（没写或写成空数组）而模块写了 `layer` 的，同样算对不上（`layer`）。
- 一个文件按清单的先后归到第一个匹配它的模块。没有模块匹配的文件归到「未归属」，在架构首页单列，不藏。
- 对不上的不让生成失败，列在架构首页的「项目判断里对不上的」，`check` 也报，共五种：一个文件被两个模块匹配（`double`：归第一个，每对模块记一条、两个都点名、写明几个文件并举头三个）；一个模块的 `paths` 一个文件也没匹配到（`empty`：模块仍在、文件为空）；`layer` 不在 `layers` 里（`layer`：这个模块的层记成 null，不进越层判断）；`id` 不合写法或重复（`id`：这个模块整个不用，它匹配的文件归后面的模块或未归属）；写法本身不成形（`format`：项不是对象、没写标题、`status` 写错、`paths` 或 `layers` 不是数组、`modules` 不是数组——整段层面的问题 `module` 记 null；`status` 写错的按 `proposed` 算、模块照用；`paths` 不成形的模块文件为空，只记这一条 `format`，不再顺带记 `empty`）。`modules` 写成空数组当作没写。
- `init` 起草的 `ignore` 多写三条：`**/*.test.*`、`**/*.spec.*`、`**/__tests__/**`——测试文件与代码放在一起的项目很常见（下游前端 485 个文件里 211 个是这样的测试文件，引用边里五分之一从它们发出），不排掉的话模块图上全是测试库。已有的配置不替人改，架构首页在文件清单里有这类名字时提醒一句。
- **没有 `modules` 时按目录分**：每个代码根目录下的每个一级子目录是一个模块（里面没有代码文件的不成模块），直接放在根目录下的文件合成一个模块（`id` 取根目录的末一段），页面上标明「按目录分的，还没有项目判断」。`id` 由目录名推出；几个目录推出同一个 `id` 时全部改用整条路径推，再撞就接 `-2`。几个代码根互相套着时，一个文件按最深的那个根算。平铺的目录这样分出来只有一个大模块——这正是要 AI 提议、人确认的地方。

## B. 取事实

### 文件

`codeRoots` 下、没被 `ignore` 排掉的每个代码文件（Python：`.py`；JS 一族：`.js` `.jsx` `.mjs` `.cjs` `.ts` `.tsx`）各取：路径、语言、行数、**文件头说明**、是不是入口。别的扩展名不扫，按扩展名报数（「没扫的文件：`.vue` 12 个」），不装作扫过。

名字以点开头的文件与目录、`__pycache__` 目录一律不进——不算扫过，也不报数：它们不是项目的来源。页面是入库的生成物，编译缓存这类不入库的文件要是算进去，同一份代码在跑过与没跑过的副本上会出两样的页面（下游一个副本的代码目录下有 654 个 `.pyc`，2026-11-23 实测：架构首页的「没扫的文件」多出一行，换一个副本 `check` 就报对不上）。别的不入库的产物（构建输出、本地数据）由配置的 `ignore` 排。押后：在 git 仓里只认入库与未忽略的文件——要让生成器依赖 git，等真有项目因为别的产物对不上再定。

- 文件头说明：Python 是文件的第一条语句若是字符串字面量（前面只许有空行、注释、编码声明），取它的内容。JS 一族取两处里先有的那一处：① 文件最前面、任何语句之前的那一块注释（`/* … */` 或连着的 `//` 行）；② 没有 ① 时，开头那一串引用语句（`import …`、`export … from …`，可以跨行）与指令（`'use client'`、`'use strict'`）之后、第一条别的语句之前的第一块注释——前端常见的写法是先引用、再在组件上方写说明（下游前端 273 个文件里取得到说明的只有 91 个，另有 62 个是这样写的，2026-11-23 实测）。夹在两条引用语句之间的注释不算，那多半是写给下一行引用看的检查指令；跟在一条引用语句同一行后面的注释算那条引用的，也不算。取的是哪一处记在 `headAt`：文件最前面的（Python 的文档字符串、JS 的 ①）记 `top`，JS 的 ② 记 `after-imports`，没有说明的为 null。② 取到的那块注释，说的有时是紧跟着的那一条定义而不是整个文件——下游前端这样新取到的 63 段里，后面紧跟组件的参数类型或组件本身的 44 段，紧跟一个常量或别的函数的 19 段（2026-11-23 实测）——所以页面上要标得出它是从哪儿取的，由读的人判断。原文照搬，只去掉引号与注释记号、统一缩进；它是「来源里的注释」，不是 AI 的说明。没有就是 null，页面上写「没有文件头说明」。
- 入口：Python 文件里有 `if __name__ == "__main__":`，或者在模块级（不缩进）定义了应用对象（`<名字> = FastAPI(…)`，可带类型标注、可写成 `fastapi.FastAPI(…)`）——这种文件由服务器进程按「文件:对象」拉起，没有 `__main__` 那一段，不认的话服务的启动文件会出现在「没有被别的文件引用的」清单里。写在函数里、条件分支里的不算。

### 引用

只认写在代码里的引用语句，字符串、注释、文档串里的不算；写在函数里、条件分支里的照认。

| 写法 | 怎么解析到文件 |
|---|---|
| Python `from .a import x`、`from ..pkg.a import x`、`from . import a` | 从这个文件所在的目录起算，一个点是本目录，每多一个点上一层 |
| Python `import a.b`、`from a.b import x` | 从几个起点依次去找（起点怎么排见下面「Python 绝对引用的起点」）；取能对上文件的最长前缀（`a/b.py` 或 `a/b/__init__.py`），几个起点一样长时取先试的那个。`from a import b` 而 `a/b.py` 存在的，指向 `a/b.py`。目录里没有 `__init__.py` 也照认；`a/` 与 `a.py` 同时存在时先认目录 |
| JS 一族 `import … from './a'`、`export … from './a'`、`require('./a')`、`import('./a')` | 相对路径依次试原样、加 `.ts` `.tsx` `.js` `.jsx` `.mjs` `.cjs`、再试 `/index` 加这些扩展名；写的是 `./a.js`（或 `.jsx`、`.mjs`、`.cjs`）而没有这个文件的，再试同名的 `.ts`、`.tsx`（`.mjs` 试 `.mts`、`.cjs` 试 `.cts`）——TypeScript 的写法是引用里写编译后的扩展名 |

**Python 绝对引用的起点**（照解释器自己找模块的先后排；2026-11-23 整期审查用合成项目找出的两类错：代码根本身是个包时，包里的 `import logging`、`from celery import …` 被接到了同目录下同名的文件上；两个代码根下有同名文件时，引用被接到了另一个根的那个文件上）：

1. 引用方所在的目录——只在它是「脚本目录」时算：目录里没有 `__init__.py`，并且目录里有入口文件（带 `__main__` 的）。脚本直接运行时，解释器先在脚本自己的目录里找。
2. 引用方自己所在的代码根（几个代码根互相套着时取最深的那个）。
3. 别的代码根，照配置里的先后。
4. 项目根。

代码根当起点时分两种：

- **平铺的**：目录里没有 `__init__.py`，或者有、但项目里没有一处引用按包的写法指进它。起点就是它自己。
- **包式的**：目录里有 `__init__.py`，并且项目里至少有一处引用按包的写法指进它——直接放在它下面的文件用了相对引用（`from . import x`、`from .x import y`），或者它子目录里的文件用相对引用退到了它这一层（`from ..x import y`），或者有文件拿它的目录名当包名引用（`import <目录名>.x`、`from <目录名> import x`）。起点是它上面第一个不含 `__init__.py` 的目录（最远到项目根），它自己不当起点：包里的 `import logging`、`from celery import …` 指的是标准库与外部包，不是同目录下同名的文件。
- 包式的代码根里，一条绝对引用照上面的起点没对上文件，而它的第一段与这个代码根下直接放着的一个文件或目录同名、又不是标准库的模块名：不成边、不记成外部包，进「没解析到的引用」，写明「按包里的绝对引用它指外部的 <名字>；同目录下有同名的 <路径>，这个目录要是直接从里面启动的，引用的就是那个文件」——两种读法都摆出来，不猜。第一段是标准库模块名的不写这一条，它指标准库（标准库的名单与判外部包时用的是同一份）。

- 解析到的记成一条边：从哪个文件、到哪个文件、在第几行、引了哪些名字（`from a import x, y as z` 的 `x`、`y`；`import a.b` 这种没有点名的记「整个文件」）。同一对文件多处引用合成一条，名字并起来。
- 相对写法却没对上文件的，进「没解析到的引用」清单（文件、行、原文）。清单里每一条的「原文」是要上页面的字，里面不许带代码的行号（行号只在 `line` 那一栏）——「同一个路由器挂了多次，只取第一处，在 <文件>」，不写「第几行」；切不动的文件写「有一处<什么>没有闭合，整个文件没扫」（<什么>是没闭合的那种东西，比如三引号字符串）。
- 对上的文件不在文件清单里（在代码根之外，或者被 `ignore` 排掉了）：不成边，进「没解析到的引用」，写明「对上了 <路径>，但它不在扫的范围里」——不许留一条指向清单外的边，页面上哪儿都看不见它。
- 不是相对写法、也没在项目里对上文件的，是外部包：只记包名的第一段（`fastapi`、`react`；带作用域的 npm 包记两段，`@scope/name`），按模块汇总，不成边。JS 一族里不是相对写法、第一段却与某个代码根下直接放着的目录或代码文件同名的（`components/Button` 而代码根下有 `components/`；`config` 而代码根下有 `config.ts`）：多半是配了基准目录的项目内引用，不记成外部包，进「没解析到的引用」写明「不是相对写法，但代码根下有同名的 <路径>」。
- Python 的 `importlib.import_module(…)`、`__import__(…)`，JS 的 `import(变量)`、`require(变量)`：参数不是字符串字面量的（含 f 串、带 `${}` 的模板），进「运行时才定的引用」清单，不成边。实参是字符串字面量、像模块名又不以点开头的，按 `import` 它解析。
- 一行里的续行（反斜杠、括号里换行）要认全；`from a import *` 记「全部名字」。JS 的 `export * from` 记整个文件。
- 一条 `from` 里有的名字对上了文件、有的没对上：没对上的那条进「没解析到的引用」。切不动的文件（词法走不完）照旧列在文件清单里、文件头说明为 null，另在「没解析到的引用」里放一条写明原因——不悄悄漏掉它。

### 接口

认一种写法——装饰器形式的 HTTP 路由（FastAPI、Starlette 与同样写法的框架）：

- `<名字> = APIRouter(prefix="…")` 定义一个路由器，`prefix` 没写就是空；`<名字> = FastAPI(…)` 定义一个应用。两种都能挂接口，差别在怎么对外：应用本来就是最外层，路由器要挂到应用（或别的路由器）上才对外；
- `@<名字>.<get|post|put|delete|patch|head|options|trace>("<路径>" …)` 后面的 `def` / `async def` 是处理函数，中间隔着别的装饰器照认；路径是第一个位置参数或 `path=`；
- `@<名字>.api_route("<路径>", methods=[…])` 按 `methods` 里的每个方法各算一个接口；没写 `methods` 的是 `GET`（框架的默认，2026-11-23 核对过 FastAPI 的源码：`if methods is None: methods = ["GET"]`）；写了但不是字面量清单的记方法 `ANY`；`@<名字>.websocket("<路径>")` 记方法 `WS`；
- `<甲>.include_router(<乙>, prefix="…")` 把乙挂到甲下面。乙可以是本文件里的路由器名字、从别的文件引进来的名字（`from .jobs import router as jobs_router`）、或引进来的模块上的属性（`jobs.router`）——借引用边找到它是哪个文件里的哪个路由器。
- 工厂函数造的路由器：模块级的 `<名字> = <函数>(…)`，而 `<函数>` 是同一个文件里定义的函数、函数体里只定义了一个路由器并且 `return` 的就是它——`<名字>` 就认成那个路由器。下游后端有两个文件这样写（2026-11-23 实测：不认的话，其中一个文件的 3 个接口原本拼得出的完整路径会变成「没找到它挂在哪」）。同一个工厂被调用了几次、各赋给不同名字又各挂了一次的，这几个名字指的是同一处定义：照下面「同一个路由器被挂了不止一次」那条办——这几条接口实际上在每一处挂载下面各有一份，清单里只列一份；路由器的前缀是工厂的参数的，照旧算不准（`runtime`）。
- `<甲>.mount("<前缀>", <乙>)`，乙是本项目里 `FastAPI(…)` 定义的应用时：等于把乙挂到甲下面，前缀是第一个位置参数（或 `path=`）。乙认不出是哪个应用的（`StaticFiles(…)` 这类）不管它，也不报。

每个接口取：方法（大写）、写在装饰器里的路径、完整路径、完整路径拼不出时的原因、处理函数名、所在文件与行、处理函数头的说明（函数体第一条语句是字符串字面量时取它，原文照搬，没有就是 null）。

完整路径 = 一路挂载的前缀（从最外层起，每一层是「甲自己的前缀 + 这处挂载写的前缀」）+ 路由器自己的前缀 + 装饰器里的路径（2026-11-23 核对过 FastAPI 的源码：登记路由时是 `self.prefix + path`，挂载时是 `self.prefix + 挂载的前缀`）：

- 应用（`FastAPI(…)`）没有被挂到别处的，是最外层，完整路径就是路径本身；
- 路由器（`APIRouter(…)`）没有被任何解析得出的挂载点到的：完整路径记 null，原因记 `unmounted`——它一定挂在某处才对外，找不到挂在哪，前面有没有前缀就不知道。原先把它当最外层、照它自己的前缀算，有一处挂载认不出时（`include_router(make_router(), prefix="/admin")`）它下面的接口就少一段前缀而不自知（2026-11-23 整期审查的反例：记成 `/users`，实际是 `/admin/users`）。一路往上有一个路由器是这样的，下面的同样记 null；
- 路径与前缀里的名字，若是**同一个文件里模块级只赋值过一次、赋的是字符串字面量**的，按它的值算；字面量与这种名字用 `+` 拼起来的照算（`BASE + "/map"`）。这是算得准的，不是猜——下游后端 226 个接口里 17 个的路径这样写，其中 15 个的名字就是同文件里的字符串常量（2026-11-23 用语法树实测）。`path` 记算出来的值。从别的文件引进来的名字，跟着引用找到那个文件，名字在那里是模块级只赋值过一次的字符串字面量的，也照算——只跟这一层，那个文件里它又是引进来的就不再跟；
- 除此之外，路径或一路上任何一段前缀算不准的（赋过不止一次的名字、函数调用、f 串、函数的参数、转了两道手引进来的名字），完整路径记 null，原因记 `runtime`，`path` 照源码的写法记，页面上标「前缀是运行时定的」；原因是 `unmounted` 的页面上标「没找到它挂在哪，前面可能还有一段前缀」。两种原因都有时记 `unmounted`；
- 同一个路由器被挂了不止一次，取源码里先出现的那一处，另几处进「没解析到的引用」写明「同一个路由器挂了多次，只取第一处」；
- 一处挂载的乙找不到是哪个路由器，而这处挂载给它加的前缀（甲一路上的前缀加这处写的）不是确定为空：进「没解析到的引用」写明「有一处挂载没解析到，它下面的完整路径可能少一段前缀」——不许悄悄当它没有。确定为空的不用报（不影响路径）；
- 挂载的甲认不出是哪个路由器（比如它是函数的参数）：乙下面的完整路径记 null、原因记 `unmounted`——甲上面还有没有前缀不知道，不猜。
- 装饰器的形状对（`@<名字>.<方法>(…)` 后面跟着函数，路径是以 `/` 开头的字符串字面量），而 `<名字>` 认不出是哪个路由器的——路由器是函数的参数、在 `if` / `else` 两个分支里各定义了一次、从外部包引进来的、同一个文件里赋成了别的东西的（`other = Thing()`：它可能是路由器的子类或工厂造出来的，静态看不出）：不进接口清单，进「没解析到的引用」，写明「像接口，但认不出它的路由器，没进接口清单」。原先这样的接口哪张清单都不进。路径不是以 `/` 开头的字面量的不报——`@mock.patch("a.b")`、`@cache.get("key")` 这类不是接口。

`routes` 按文件、行排序。别的框架的路由读不出来：一个接口也没读到时，页面上写「没有读出接口（只认装饰器写法的路由）」，不留空白。

### 汇总成模块

- 每个模块：它的文件（连同行数、文件头说明）、接口、读写的表（取自第一期的代码扫描，按文件归到模块）、用到的外部包。
- 模块之间的依赖：甲模块的文件引用了乙模块的文件，甲就依赖乙；记下是哪几对文件、用了乙的哪些名字。模块自己内部的引用不算依赖。
- 对外提供的名字：一个模块的文件里被别的模块引用到的名字，连同是哪个文件的、被哪几个模块用。
- **结构上看得出的**（都是机械算的，页面上明说是算出来的，不下「这是债务」的判断）：模块之间的循环依赖（列出成环的模块与造成环的文件对）；`layers` 有定义时，下层模块引用上层模块的「越层引用」；超过 1000 行的文件；既不是入口、也没有被任何文件引用的文件。

`build --facts-json` 多出 `code`（Task 3.1、3.2）与 `arch`（Task 3.3）。`code` 的形状：

```
"code": {
  "files":      [{ "path", "lang": "python" | "js", "lines", "head": "<文件头说明>" | null, "headAt": "top" | "after-imports" | null, "entry": true | false,
                   "externals": ["<外部包名的第一段>", …] }],
  "edges":      [{ "from", "to", "lines": [<第几行>, …], "names": ["<引的名字>", …], "whole": true | false, "star": true | false }],
  "unresolved": [{ "file", "line", "text": "<引用语句的原文>" }],
  "dynamic":    [{ "file", "line", "text" }],
  "skipped":    [{ "ext": ".vue", "count": 12 }],
  "routes":     [{ "file", "line", "method": "GET", "path", "fullPath": "<完整路径>" | null, "why": null | "runtime" | "unmounted",
                   "handler", "doc": "<说明>" | null }]
}
```

`why` 只在 `fullPath` 为 null 时有值，说的是为什么拼不出（见上面「接口」）；模块里的 `routes` 同样带这一栏。

- 各清单都排好序（`files` 按路径；`edges` 按 `from`、`to`；别的按文件、行），路径一律相对项目根、用 `/`。
- `edges` 一对文件一条：`names` 是排序去重后的名字；有任何一处引的是整个文件（`import a.b`、`import * as x from`、只为副作用的 `import './a'`、`require`）时 `whole` 为 true；有 `from a import *` 时 `star` 为 true。JS 的默认导入记名字 `default`。文件引用自己的不算。
- `externals` 不含语言自带的库（Python 的标准库连同 `__future__`、Node 的内置模块）。
- 相对写法对上了一个不是代码的文件（样式表、JSON、图片）的，不成边也不进「没解析到的」。JS 里 `@/`、`~/` 这类别名开头的现在不解析，进「没解析到的引用」。
- 没配 `codeRoots` 的项目 `code` 各清单都是空的。

`arch` 的形状（Task 3.3）：

```
"arch": {
  "source":  "map" | "dirs",                       // 模块取自项目判断，还是按目录分的
  "layers":  ["<层名>", …],                         // 没有就是 []
  "modules": [{
    "id", "title", "layer": "<层名>" | null, "status": "proposed" | "confirmed" | "default",
    "files":    ["<路径>", …],                      // 排序
    "lines":    <各文件行数之和>,
    "routes":   [{ "method", "path", "fullPath", "why", "handler", "file" }, …],
    "uses":     [{ "module": "<它依赖的模块 id>", "pairs": [["<本模块的文件>", "<对方的文件>"], …], "names": ["<用到的名字>", …] }],
    "usedBy":   ["<依赖它的模块 id>", …],
    "provides": [{ "name", "file", "by": ["<用它的模块 id>", …] }],
    "tables":   { "reads": ["<表名>", …], "writes": ["<表名>", …] },
    "externals": ["<外部包>", …]
  }],
  "unassigned": ["<没有模块匹配的文件>", …],
  "cycles":  [{ "modules": ["<id>", …], "pairs": [["<文件>", "<文件>"], …] }],
  "upward":  [{ "from": "<下层的模块 id>", "to": "<上层的模块 id>", "pairs": [[…], …] }],
  "big":     [{ "file", "lines" }],                // 超过 1000 行的
  "idle":    ["<既不是入口、也没有被任何文件引用的文件>", …],
  "problems": [{ "kind": "double" | "empty" | "layer" | "id" | "format", "module": "<id>" | null, "detail": "<给人看的一句话>" }]
}
```

- 模块按 `map.json` 里的先后排；`dirs` 时按路径排，`status` 为 `default`，`id` 由目录名推出。各清单里的文件、名字、表都排序去重。
- `uses` 只算跨模块的引用；整个文件被引用的与 `from a import *` 的，在 `provides` 与 `uses` 的 `names` 里都记名字 `*`。模块 id 的清单（`uses`、`usedBy`、`by`、`cycles` 里的模块）按模块在清单里的先后排；文件、名字、表按字母排。
- `tables` 连同项目判断里 `dynamicTables` 补上的读写一起算，与表页上「谁在写、谁在读」是同一份。
- `big` 与 `idle` 看全部代码文件，未归属的也算。一个包里只要有文件被引用，它的 `__init__.py` 就不算没人引用。JS 一族没有「入口」的写法可认，它的入口文件会出现在 `idle` 里——页面上这张清单的标题要说得出这一点（「没有被项目里别的文件引用的：入口、脚本，或者真的没人用」）。
- 「未归属」不是一个模块：它的文件不进 `modules`，引用到它们或从它们发出的边不计入任何模块的依赖，只在首页单列。
- 没配 `codeRoots` 的项目 `arch` 的 `modules` 是空数组，不出架构这一份。配了 `codeRoots` 而一个代码文件都没取到的（比如目录下只有没扫的扩展名）同样是空数组——哪怕 `map.json` 里写了模块：没有代码文件就没有可汇总的事实，出一份空壳只会让人以为扫过。

## C. 说明

新增两种锚点，照旧只经 `note put` 落盘、由命令盖指纹：

| 锚点 | 写什么 | 绑定的来源切片 |
|---|---|---|
| `module:<id>` | 第一段一句话：这个模块管什么（清单页拿它当这一行）。后面按需要写：不管什么、一次典型的调用从哪进到哪出、改它要小心什么 | 模块的 id 与标题、排序后的文件清单、接口（方法加完整路径）、它依赖的模块 |
| `doc:arch` | 整个系统的导读：由哪几块组成、数据怎么流、从哪一块读起 | 各模块的 id、标题与所在的层 |

函数体改了不算来源变了；加了文件、多了接口、多依赖了一个模块才算。切片里的接口记「方法加完整路径」，完整路径为 null 的用源码里的写法。有模块才有 `doc:arch` 这个锚点。`pending --json` 给每个待写的模块附一份 4KB 以内的上下文（文件与文件头说明的头一句、接口、依赖与被依赖、读写的表；装不下的截断并写明还有多少）。上下文里取自来源的字（路径、接口的路径与完整路径、文件头说明）都过隐去——它会被贴进派单与日志。

## D. 页面

配了 `codeRoots`、取得到代码文件的项目才出这一份；出的页面：

- `docs/readable/arch/index.html`（架构首页），自上而下：
  1. 导读（`doc:arch` 的说明；没写时写明「还没有导读」）；
  2. 总图；
  3. 模块清单：每个模块一行——标题与 id、所在的层、一句话职责（`module:` 说明的第一段，没写时空着并标「待写」）、文件数、规模（约多少行）、接口数、读几张表、写几张表、依赖几个模块、被几个模块依赖；
  4. 结构上看得出的（标题下面一句话写明「这几张清单都是照引用关系算出来的事实，算不算问题由人判断」）：循环依赖（每组列出成员模块、每一对模块之间各有几对文件，文件对的明细收在可展开的区里）、越层引用（`layers` 有定义时才有这一段）、超过 1000 行的文件、没有被项目里别的文件引用的（标题写明「入口、脚本，或者真的没人用」）；

  6. 文件清单里有名字带 `.test.`、`.spec.` 或在 `__tests__/` 下的文件时提醒一句：测试文件进了模块图，可以在配置的 `ignore` 里排掉；
  7. 现有架构文档的入口（Task 3.5，没有 `archDocs` 时不出这一段）。
- `docs/readable/arch/m-<id>.html`：每个模块一页，自成一体，自上而下：说明 → 邻居图（它依赖谁、谁依赖它，只画一跳）→ 接口（方法、完整路径、处理函数、所在文件、处理函数的说明）→ 文件（路径、规模档、是不是入口、**文件头说明的全文**）→ 它依赖的模块（每个：通过哪几对文件、用了哪些名字）→ 对外提供的名字（名字、在哪个文件、被哪几个模块用）→ 读写的表（表名链到数据库设计里那张表的页面，标读、写）→ 用到的外部包。哪一段没有内容就写「没有」。
- `docs/readable/arch/routes.html`：全部接口一张表，按完整路径排（拼不出完整路径的排在最后、照源码的写法显示，并照原因标「前缀是运行时定的」或「没找到它挂在哪，前面可能还有一段前缀」；模块页的接口同样标），带所属模块并链过去。一个接口都没读到时这一页照出，写「没有读出接口（只认装饰器写法的路由）」。
- `docs/readable/index.html` 的文档清单里多一项「架构设计」。
- 数据库设计的表页上，「谁在写」「谁在读」的每个文件后面标出它所属的模块并链到模块页（未归属的文件标「未归属」）；没有架构这一份的项目，表页与现在逐字节相同。

**确切的行数不上页面**（事实里照旧有）。页面是入库的生成物：写上确切的行数，代码随便加三行，模块页与首页就跟着变，每次提交都带一批没有内容的页面差异——与第一期「代码文件的行号不上页面」是同一个道理。页面上只写规模：文件按四档——`不到 100 行`、`100–500 行`、`500–1000 行`、`1000 行以上`（「超过 1000 行的文件」那张清单只列文件，不写行数）；模块与全库的行数写「约 N 行」，模块取一位有效数字、全库取两位（`约 300 行`、`约 5 千行`、`约 12 万行`）；不到 100 行的一律写 `不到 100 行`——只有二三十行的小项目，取有效数字等于写确切的数。文件数、接口数、表数这些照实写——它们变了就是结构真的变了。

文件头说明与处理函数的说明是「来源里的注释」，原文完整上页面，不截断、不改写——接手的人看一个文件、一个接口是干什么的，就看它；它们与 AI 写的「说明」在页面上标得出区别。

总图一张图只画一件事：按层排出模块的方框（没有 `layers` 就排成几行），方框里写标题与文件数，点了到那个模块的页面；模块不超过 12 个时画模块之间的线，超过时只画层与层之间的线并写上跨层的文件对数——模块自己的关系看它那一页的邻居图。

每一块内容照旧标来历：「取自来源」「来源里的注释」「说明 · 草稿 / 已抽审」「项目判断 · AI 提议 / 人已确认 / 按目录分的」；说明过期的照第一期的办法原文照显并加横条，横条在第一期那句话后面再补半句为什么：「写完之后这个模块的文件、接口或依赖变了，这段说明可能已经过期」。代码文件的行号不上页面（与第一期同一个道理）。页面上凡取自来源的字（路径、名字、接口路径、文件头说明、处理函数的说明）都过隐去，落盘前的兜底同样管这几页。确定性、原子落盘、每页自成一体、能打印，都与第一期相同。

机器读得回来（沿用第一期表页的做法：一行一条、带 `data-row`，要比的格子带 `data-k`，核对器靠它们把页面读回来）：

| 页面 | 段（`data-section`） | `data-row` 的值 | 要比的格子（`data-k`） |
|---|---|---|---|
| 模块页（根元素带 `data-anchor="module:<id>"`；`<h1>` 的字是模块的标题） | `files` | 文件路径 | `key`（显示的路径）、`size`（规模档）、`entry`（`是` 或空）、`head`（文件头说明的全文；没有说明的这一格不带 `data-k`）、`headAt`（只在说明取自引用语句之后时有：那一格里说明上方标一句「写在引用语句之后的第一块注释」；取自文件最前面的不带） |
| | `routes` | `<方法> <完整路径，拼不出的用源码里的写法>` | `method`、`path`、`handler`、`file`（所在文件）、`doc`（处理函数说明的全文；没有的不带）、`why`（拼不出完整路径时那句标记的字；拼得出的不带） |
| | `uses` | 对方的模块 id | `module`（显示的 id）、`names`（用到的名字，按字母排，逗号加空格隔开） |
| | `usedBy` | 依赖它的模块 id | `module` |
| | `provides` | `<文件路径>#<名字>` | `name`、`file`、`by`（用它的各模块 id，空格隔开） |
| | `tables` | 表名 | `key`（显示的表名）、`rw`（`读`、`写` 或 `读写`） |
| | `externals` | 包名 | `key` |
| 架构首页 | `modules` | 模块 id | `module`（显示的 id）、`files`、`lines`（约多少行——核对器照 D 节取整的规矩自己从事实算）、`routes`、`reads`、`writes`、`uses`、`usedBy`（后四个是读几张表、写几张表、依赖几个模块、被几个模块依赖） |
| | `unassigned`、`big`、`idle` | 文件路径 | `key` |
| | `cycles` | 这一组的成员 id（照模块清单的先后，空格隔开） | `pairs`（这一组有几对文件） |
| | `upward`（有层才有这一段） | `<下层的模块 id> <上层的模块 id>` | `pairs`（几对文件） |
| | `unresolved`、`dynamic` | 文件路径（同一个文件可以有几行） | `key`、`text`（那一条的原文） |
| | `skipped` | 扩展名（没有扩展名的为空） | `count` |
| | `problems` | `<种类> <模块 id，没有的为空>` | `detail` |
| | `archDocs`（配了现有的架构文档才有这一段） | 那份文档的路径 | `key`、`chapters`（几章）、`blocks`（几块） |
| 接口总表 | `routes` | 同模块页的接口 | `method`、`path`、`handler`、`file`、`why`、`module`（模块 id，未归属的写 `未归属`）。处理函数的说明只在模块页上，总表不放：两百多行的表再加一栏长文字，拿着地址来查就不好用了 |
| 表页 | 谁在写、谁在读的每个文件 | 沿用第一期 | `file`（显示的路径）、`module`（模块 id，未归属的写 `未归属`） |

各段的容器带 `data-section`，好让核对器知道哪一行属于哪一段；某一段没有内容（页面上写「没有」）时容器照样在。**键不许只放在属性里**：`data-row` 是给核对器配行用的，读者看到的是格子里的字，所以每一行显示键的那一格都带 `data-k`（上表里的 `key`、`module`、`name` 与 `file`），核对器要比它显示的字。原先键只在 `data-row` 里，出页面的代码把显示的路径、模块写错了，`check` 照样报「不一致 0 条」（2026-11-23 整期审查用三处突变实测）。

**现有的架构文档**（`archDocs`，Task 3.5）：每一份照人读版需求规格的办法逐块换排成网页，一个字不加不少，零丢失的核对同样管它。它是「旧文档」，不是现行事实，也不是 AI 的说明。

- 只认 Markdown（`.md`）；写了别的扩展名、同一个路径写了两遍，退出码 2 并点名。
- 第 i 份（照配置里的先后，从 01 起）出在 `arch/doc-<两位序号>/index.html`（清单页）与 `arch/doc-<两位序号>/s-<两位章号>.html`。分章、块的属性、条目的地址、图、本章条目、隐去与隐去清单，都与需求规格那一份是同一套代码、同一套规矩（第二期契约 B、C 节），只换这几样：
  - 文档名取它的第一个一级标题，没有就取文件名；面包屑是「文档首页 › 架构设计 › <文档名> › <章名>」；
  - 清单页与各章页顶上都有一条横条，原话：「这是 <路径> 的原文，写的时候对应的代码以它自己标的版本为准；现行的结构以架构首页为准。」其中「架构首页」链到架构首页。横条不带 `data-block`，读回页面时不算任何一块的字；
  - 页面上写来源的那几句，路径是这份文档的路径；
  - 块的锚点（`data-anchor`）前面加上 `archdoc:<两位序号>/`（`archdoc:01/spec:…`、`archdoc:01/req:REQ-…`），条目的 `id` 一律取「`a-` 加锚点指纹的前 8 位」。旧文档里的条目也可能以 `[REQ-…]` 开头，不加这一截就与需求规格那一份的锚点撞名——往后按锚点做需求到页面的关联时，同一个锚点只许指一处。这一截只加在页面上；事实里各份自己的块，锚点照第二期的规矩出、不带它。
- 架构首页第 7 段「现有的架构文档」：段首一句「下面是项目里原有的文档，原文照排；写的时候对应的代码可能已经变了，现行的结构以本页上面几段为准」，然后每份一行——文档名（链到它的清单页）、来源的路径、几章、几块。这一段排在首页很靠后的地方（真数据上首页有十来屏），所以首页开头那句报数的话后面接半句「项目原有的架构文档 N 份，列在本页末尾」，链到这一段；没配的不接。
- 事实：`build --facts-json` 多出 `archDocs: [{ "file", "blocks": […], … }]`，每一项与 `spec` 同一个形状；切块的还原自检同样管，不过的退出码 3、点名是哪一份的第几行。没配的是空数组。
- 没有架构这一份的项目（没有模块）配了 `archDocs`：这些页面不出，`build` 的报数里写明「配了 archDocs，但这个项目没有架构这一份，没出」。
- `build` 的报数多一行：现有架构文档几份、共几章几块、隐去几处。`check` 的摘要多一句：几份、几块、页面上读回几块。
- 加了 `archDocs` 前后，需求规格那一份（`spec/` 下）与数据库设计的页面逐字节相同；没配 `archDocs` 的项目整套页面与之前逐字节相同。

## E. 核对

`check` 多查：

- 页面上显示的与重新取的事实逐项相同（核对器自己读页面，不用出页面的函数；`kind` 用 `arch-mismatch`，点到是哪个模块的哪一项）。比的就是 D 节那张表：每一段的行与事实里的条目一条不多、一条不少（同一个键有几行的按个数比），每一行里带 `data-k` 的格子显示的字与事实里对应的值相同——规模档、约多少行这类由事实算出来的，核对器照同一条规矩自己算；文字先过隐去、空白归一再比；文件头说明与处理函数的说明比全文。表里列了的段在页面上不见了、表里要求有的格子页面上没有、行里出现了表里没列的 `data-k`，都算对不上——出页面的代码新加一格而核对没跟上，也在这里露出来。模块页 `<h1>` 的字要等于模块的标题；
- 第一期表页的两处键同样补上：字段表每一行显示的列名、「谁在写」「谁在读」每一行显示的文件路径，显示的字与事实比（`kind` 沿用 `fact-mismatch`）；
- `module:` 与 `doc:arch` 的说明过期、成了孤儿（模块被删或改了 id）；
- 项目判断里对不上的各算一条，`kind` 用 `arch-map`（与页面对不上事实的 `arch-mismatch` 分开——一个要人去改 `map.json`，一个要人去重出或查出页面的代码）；
- 现有架构文档的逐块投影一块不少、一字不差：对每一份跑第二期那一项，`kind` 沿用那七种，`where` 里写明是哪一份的路径。验证用的动作：把 `arch/doc-01/` 某一章页上的一块改掉一个字 → `check` 点名这份文档的路径与来源的行。测试注入点两个，都落在第一份上：`READABLE_FAIL_AT=arch-doc-cut` 切出来的第一块带字的少一个字，还原自检拦下（退出码 3、什么都不出、点名是哪一份的第几行）；`arch-doc-render` 出页面时丢一个字，落盘前的自检拦下（退出码 3、原有页面不动）。没配 `archDocs` 或没有架构这一份时设了它们，直接报错。

验证用的动作：给一个模块加一个文件而不重出 → `check` 退出码 1；把页面上某个模块的一条接口删掉 → 点名；把一个模块的 `paths` 改得一个文件都匹配不到 → 点名。

测试注入点（出页面的代码故意出错，落盘前的自检应当拦下：`build` 退出码 3、原有页面不动、点名哪一页哪一项）：`READABLE_FAIL_AT=arch-render` 第一个有文件的模块页上漏掉第一个文件那一行（原有）；`arch-show-key` 第一个有文件的模块页上第一个文件显示的路径写错、`data-row` 不动；`arch-show-head` 第一条文件头说明少最后一个字；`arch-drop-section` 架构首页「没有被项目里别的文件引用的」那一段整段不出。注入点找不到可下手的地方（没有文件、没有文件头说明，或者这个项目根本没有架构这一份）时直接报错、退出码 3，不许悄悄什么都不做。

## F. 测试预算

测试代码不超过有效代码的一半，按风险给：

- 引用：相对引用上几层；绝对引用经代码根目录找到；`from 包 import 子模块`；括号里换行的多名字；字符串与注释里的 `import` 不算；函数里的照认；JS 的扩展名与 `index` 补全；没对上的相对引用进清单而不成边；运行时才定的进清单。
- 接口：前缀一路拼对；`include_router` 带前缀；前缀不是字面量时完整路径为 null 并明说；处理函数的说明取到；别的框架一个都读不出时页面明说。
- 模块：通配归属、先到先得、未归属、对不上的四种；没有 `modules` 时按目录分；循环依赖与越层引用各一例，对照没有环的。
- 页面与核对：每个模块一页；改事实不重出、手改页面，`check` 各自点名；说明的过期（加文件）与不过期（改函数体）；没有架构这一份时数据库页面逐字节不变；两次生成逐字节相同。
- 整期审查之后补的（2026-11-23）：
  - 取事实：JS 一族写在引用语句后面的文件头说明取得到、夹在引用之间的不算；模块级的 `FastAPI(…)` 算入口、写在函数里的不算；`__pycache__` 里的文件不进「没扫的文件」；包式的代码根里与标准库、外部包同名的文件不被接成边，外部包同名的那条进「没解析到的引用」；有 `__init__.py` 却全用平铺写法的代码根照旧成边；脚本目录里引用同目录的文件成边；两个代码根下有同名文件时接到引用方自己那个根的；对上了清单外的文件的进「没解析到的引用」；没被挂载的路由器完整路径为 null、原因 `unmounted`，没被挂载的应用照旧算；`mount` 挂的子应用带上前缀；认不出路由器的接口进「没解析到的引用」而 `@mock.patch("a.b")` 不进；`.trace` 认得；「没解析到的引用」的原文里没有行号（代码顶上加三行，页面逐字节不变——夹具里要有切不动的文件与挂了两次的路由器）。
