## A. 配置（Task 1.1）

`docs/readable-src/config.json`：

```json
{
  "version": 1,
  "title": "项目名",
  "spec": "Product-Spec.md",
  "ddl": ["conflation/api/schema.sql"],
  "codeRoots": ["conflation/api", "conflation/web/src"],
  "ignore": ["**/tests/**", "**/node_modules/**"]
}
```

- `ddl` 按执行顺序列出建表定义文件，后面的文件能改前面建的表。
- `init`：配置不存在时起草一份——`title` 取根目录名；`ddl` 依次找 `**/schema.sql`、`**/sql/*.sql`、`**/migrations/*.sql`（同一目录按文件名排序，三种找法的结果都收、去重），找不到就写空数组并在输出里说明——lutetia 的建表文件在 `lutetia/sql/001…009_*.sql`，只找根目录下的 `sql/` 会一张表都找不到；`codeRoots` 取含 `.py` / `.ts` / `.tsx` 文件最多的两个顶层目录。配置已存在时一个字节不动，输出「配置已存在」，退出码 0。
- 配置里的路径不存在：`build` 退出码 2，点名是哪一条。绝对路径、用 `..` 越出根目录的路径同样退出码 2——生成器只读根目录以内的东西。

## B. 建表定义的取事实器（Task 1.1）

方言以 PostgreSQL 为准。

**切语句**：以分号结束；认得 `--` 行注释、`/* */` 块注释、单引号字符串（含 `''` 转义）、`$$…$$` 与 `$标签$…$标签$`，这些里面的分号不算结束。

**认这些语句**（大小写不敏感，名字可带双引号与模式前缀，模式前缀丢弃）：
- `CREATE TABLE [IF NOT EXISTS] 名 ( … )`
- `ALTER TABLE [IF EXISTS] [ONLY] 名 ADD [COLUMN] [IF NOT EXISTS] 列定义`
- `ALTER TABLE … DROP [COLUMN] [IF EXISTS] 列`
- `ALTER TABLE … ALTER [COLUMN] 列 SET NOT NULL | DROP NOT NULL | SET DEFAULT 值 | DROP DEFAULT | TYPE 类型`
- `ALTER TABLE … RENAME [COLUMN] 旧 TO 新`
- `ALTER TABLE … ADD [CONSTRAINT 名] PRIMARY KEY | UNIQUE | FOREIGN KEY | CHECK …`
- `CREATE [UNIQUE] INDEX [IF NOT EXISTS] 名 ON 表 [USING 方法] ( … ) [WHERE …]`
- `COMMENT ON TABLE 表 IS '…'`、`COMMENT ON COLUMN 表.列 IS '…'`
- `ALTER TABLE … DROP CONSTRAINT [IF EXISTS] 名 [CASCADE | RESTRICT]`：按名字摘掉约束，行内约束按下面的自动名字找
- `DROP INDEX [IF EXISTS] 名`：摘掉索引
- `ALTER TABLE … VALIDATE CONSTRAINT 名`：不改结构，略过
- `CREATE [OR REPLACE] VIEW 名 AS …`：记成视图——名字、文件与行、定义原文
- `CREATE [OR REPLACE] FUNCTION 名(…)`：记成数据库函数——名字、文件与行、签名那一行
- 一条 `ALTER TABLE` 里用逗号连着的多个动作，逐个处理。
- 列定义里的 `GENERATED { ALWAYS | BY DEFAULT } AS IDENTITY [ ( … ) ]` 与 `GENERATED ALWAYS AS ( 表达式 ) STORED`：是列的属性，原文记在列的 `generated`，不许因为它把整张表丢进「未解析」。
- `CREATE MATERIALIZED VIEW 名 AS …`：记成视图，`materialized` 为 true。
- `DROP COLUMN` 连带摘掉点到这一列的表级约束与索引；被摘的是主键时，其余列的主键标记一并清掉——库里就是这么做的，不摘就是把不存在的约束标成「取自来源」。
- `RENAME COLUMN` 把本表约束与索引里的列名、别的表外键指向它的列名一并改过来。

**没写名字的约束按库的规矩补一个名字，只在内部用**，这样后面按名字删它的语句才对得上：主键 `<表>_pkey`；唯一 `<表>_<列>_key`；外键 `<表>_<列>_fkey`（这两种多列的把列名用下划线连起来）；CHECK 的表达式恰好点到本表一列的叫 `<表>_<列>_check`，点到几列或一列都没点到的叫 `<表>_check`。补的名字不进输出：库里实际的名字还会被截到 63 字节以内、重名的在后面接数字，静态算不准，写出来就是把推断当事实——输出里没写名字的约束 `name` 为 null，页面上写「未命名」。conflation 按旧写法补出来的名字里有 24 个超过 63 字节（2026-11-23 实数）。没写名字的索引同样补一个内部名 `<表>_<列…>_idx`，输出里 `name` 仍为 null。`DROP CONSTRAINT` 命中一条行内约束时，把它从那个列上摘掉。名字找不到：不带 `IF EXISTS` 的记进「定义冲突」；带的跳过，但如果之后也没有语句再加一条同名的约束，就记进那张表的 `maybeDropped`（文件、行、名字）——库里自动起的名字可能被截短或加了数字，这条语句也许真删掉了什么，静态看不出来，得让读者知道。

**合并成现行结构**：按文件顺序、文件内按出现顺序执行。`ADD COLUMN IF NOT EXISTS` 遇到已有的列则跳过，保留先前的定义；没有 `IF NOT EXISTS` 而列已存在，记进「定义冲突」清单，仍保留先前的定义。列的顺序是首次出现的顺序。

**`DO` 块里读得出的那一种要并进来**：PostgreSQL 的 `ADD CONSTRAINT` 没有 `IF NOT EXISTS`，所以常见的写法是在 `DO` 块里先查系统表、没有才加——

```sql
DO $$ BEGIN
    IF NOT EXISTS (SELECT 1 FROM pg_constraint WHERE conname = 'fk_items_order') THEN
        ALTER TABLE order_items ADD CONSTRAINT fk_items_order FOREIGN KEY (order_id) REFERENCES orders(id);
    END IF;
END $$;
```

这种守卫只是为了重复执行不报错，执行完的结果是确定的：那条约束在。所以块体里的语句，凡是套在 `IF NOT EXISTS ( 查系统表 ) THEN … END IF;` 这一层守卫里、自身是完整的静态 `ALTER TABLE …` 或 `CREATE [UNIQUE] INDEX …`（不经 `EXECUTE`、不带 `%I` 这类占位、不在循环里）的，照「已有同名的就跳过」并进现行结构，出处写它在文件里的那一行。守卫查的系统表认 `pg_constraint`、`pg_indexes`、`pg_class`、`information_schema` 下的几张。一个守卫里静态语句不止一条时按顺序逐条并，先 `DROP CONSTRAINT IF EXISTS` 再 `ADD` 的写法也在内。不认的形状照旧进「未合并」：条件不是单独一个 `NOT EXISTS ( … )` 的（前面还 `AND` 着别的判断）、带 `ELSE` / `ELSIF` 的、判断套判断的、块外层带 `EXCEPTION` 的（出了错会被吞掉，执行完那条在不在说不准）、守卫的子查询里连了别的表的。一个块里的语句全并进来了，这个块就不进「未合并」；只并了一部分的，块照旧进「未合并」，`head` 取第一条没并的语句，`tables` 只列没并的那些语句点到的表。下游一个项目的建表文件里 102 条 `ADD CONSTRAINT` 有 87 条是这么写的，其中 47 条外键——不并，整组表之间的关系图就是空的（2026-11-23 实数）。

**读不出的要说**：
- `DO` 块（`DO $$ … $$`）里出现 `ALTER TABLE`、`CREATE TABLE`、`CREATE INDEX`、`DROP TABLE`、`DROP INDEX` 的，不合并，记进「未合并的动态定义」：文件、起始行、块内首条相关语句的前 80 个字符、块里点到的表名（`ALTER TABLE` / `ON` 后面的名字；名字是 `%I` 这类占位的记成「动态表名」）。块里只有别的东西（比如 `CREATE ROLE`）的不记——那不是表结构。一张表被某个未合并的块点到，就说明它在库里的约束可能与文档不一致：conflation 有一处块在运行时删掉某列的 CHECK 再重加一条更宽的，静态看那张表会同时有新旧两条。
- 形状是 `CREATE TABLE` 却解析不了的，记进「未解析的语句」：文件、行、前 80 个字符。不猜。
- 针对一张从没建过的表的 `ALTER`，记进「改了不存在的表」。

**每张表取**：名字、定义所在的文件与行、列、表级约束、索引、注释、指纹。
**每个列取**：名字、类型（原文，从列名之后到第一个约束关键字之前）、可否为空（有 `NOT NULL`、是主键、或是标识列 `GENERATED … AS IDENTITY` 则否——库会把标识列自动设成不可空）、默认值（原文）、是否主键、是否唯一、引用（表、列、`ON DELETE` 动作）、`CHECK` 原文、注释、指纹。
**注释从哪来**：紧贴在 `CREATE TABLE` 上方、中间没有空行的连续 `--` 行是表的注释，上方没有时取 `CREATE TABLE 名 (` 那一行行尾的 `--`；列定义所在行行尾的 `--` 是该列的注释；表体内紧贴在某列上方的整行 `--` 也归该列；`ALTER TABLE … ADD COLUMN` 那一行行尾的 `--` 归它加进来的列；`COMMENT ON` 覆盖以上各种。
**建表之后的改动**：紧贴在一条 `ALTER TABLE` 上方的连续 `--` 行不归任何一个列——它多半在讲这一批改动为什么做，一段话常常管着后面好几条语句。记成那张表的一条改动备注：那段注释第一行的行号、注释原文、紧跟其后中间没有空行的那几条针对同一张表的 `ALTER` 真正加进来的列名（被 `IF NOT EXISTS` 跳过的不算；一列都没加的也照记，列名为空）。conflation 有一段四行的注释紧贴在一条加列语句上方，后三行讲的却是再下面那个 `DO` 块，归给那个列就挂错了；1028 列里带注释的只有十几列，说明多写在 `ALTER` 上方（2026-11-23 实数）。改动备注不进指纹。

**指纹**：对规范形算 SHA-256，取前 12 位十六进制。表的规范形是按固定键序序列化的结构（列按顺序、约束、索引按名字排序、注释）；列的规范形是它自己的定义加注释。

`build --facts-json` 只取事实、不出页面，把文档模型打到标准输出：`{"tables":[…],"views":[…],"functions":[…],"unfolded":[…],"unparsed":[…],"conflicts":[…],"orphanAlters":[…]}`，表、视图、函数各按名字排序。`unfolded` 的每项是 `{"file","line","head","tables":[…]}`；视图是 `{"anchor":"view:<名>","name","file","line","sql"}`；函数是 `{"anchor":"function:<名>","name","file","line","signature"}`，同名重载的在锚点后面接参数原文指纹的前 6 位（`function:<名>#a1b2c3`），只有一个的不接。

输出里的键名（页面与核对器按这个读；没有的值写 null，不省略键）：
- 表：`anchor`、`name`、`file`、`line`、`comment`、`columns`、`constraints`、`indexes`、`changes`、`maybeDropped`、`fingerprint`。
- 列：`anchor`、`name`、`type`、`nullable`、`default`、`primaryKey`、`unique`、`references`（`table`、`column`、`onDelete`、`onUpdate`、`raw`）、`check`、`generated`、`comment`、`file`、`line`、`fingerprint`。
- 表级约束：`name`（没写名字的为 null）、`type`（`primary key` / `unique` / `foreign key` / `check`）、`columns`、`references`、`check`、`comment`、`raw`、`file`、`line`。
- 索引：`name`、`unique`、`method`、`columns`、`options`、`where`、`file`、`line`。
- 改动备注（`changes` 的每项）：`file`、`line`、`comment`、`addedColumns`。建表文件不止一份时，改它的语句可以写在靠后的文件里，光有行号找不到出处。

建表定义的取事实器可以拆成两个文件（切词切语句一个、解析与合并一个），单个文件别超过四百行。

## C. 数据库设计页面（Task 1.2）

`build` 把页面写到 `docs/readable/`：

- `index.html`：文档集首页，列出已经生成的各份文档（第一期只有数据库设计）。
- `db/index.html`：分组清单（组名、表数、每张表一行带一句注释）；接着是视图与数据库函数两张清单（名字、出处，视图带定义原文）；下面依次是「未合并的动态定义」「未解析的语句」「定义冲突」「改了不存在的表」四张清单，空的不显示。
- `db/g-<组>.html`：一组一页，顶上是这一组的关系图，下面是组内各表的摘要与链接。
- `db/t-<表名>.html`：一张表一页——名字、出处（文件与行）、注释、字段表（序号、名字、类型、可空、默认、键与约束、引用、注释）、表级约束（类型、名字、列、原文）、索引、它引用了谁、谁引用了它、所在的组、「说明」区；有改动备注的加一节「建表之后的改动」，一条一行：第几行、加了哪些列、注释原文（标「来源里的注释」）；没写名字的约束写「未命名」。有 `maybeDropped` 的表，页面顶上加一条提示「这张表有 N 条按名字删约束的语句没对上任何约束，下面的约束里可能有库里已经删掉的」，列出处与名字。被未合并的动态定义点到的表，页面顶上加一条提示：「这张表有 N 处要到库里运行时才生效的改动没有并进来，下面的约束可能与库里不一致」，并列出那几处的文件与行。

**分组**：没有项目判断文件时，按表名第一个下划线之前的那一段分组；只有一张表的组并进「其它」；一组超过 12 张表的按名字顺序切成几页（`design-1`、`design-2`），均分（15 张切成 8 加 7）。「其它」这一组的文件名用 `g-_other.html`；表名、组名里小写字母、数字、下划线、连字符以外的字符（大写字母也算），在文件名里写成 `~` 加十六进制码点——中文文件名离线拷贝、解压时容易乱码，只差大小写的两个名字在不分大小写的文件系统上会互相覆盖。说明的侧车文件名同一个推法。

**关系图**：内联 SVG。每张表一个方框，写表名与主键、外键列；方框里每条外键都写出「→ 目标表」，组内的也写，组内的另画连线——线一多，光看线分不清哪条外键指向谁。简单分层排布，不求好看；一张图最多 12 张表。

**出处标记**：页面上每段内容标它的来历。第一期出现三种：「取自来源」（结构）、「来源里的注释」（`--` 与 `COMMENT ON`）、「说明」（AI 写的；Task 1.4 之前这一区写「说明：未写」）。

**每页自成一体**：样式内联，不引外部文件，不联网；页与页之间用相对链接。

**读得全**：字段表「含义」一栏不窄于表宽的三成（字段的含义是这张表里最要读的字）。字段表在 1280 宽的窗口里不出横向滚动条，长的内容折行，注释一栏不许被挤出可见区域；窄屏才允许表格在自己的框里横向滚。约束与索引的原文显示前把连续空白压成一个空格，视图定义保留换行。表名做成链接时，链接的下划线不许盖住名字里的下划线（盖住了看着像空格）。清单页与组页里一组一张的小表，各栏宽度要一致，不许每张表各排各的。「谁引用了它」这类清单超过 8 条的收进可展开的区，免得把字段表挤到几屏之后。打印时内容不被裁掉。

**机器读得回来**（核对器靠这些把页面上显示的东西读回来，与重新取的事实比）：表页的 `<main>` 带 `data-anchor="table:<表>"`；字段表每一行带 `data-anchor="column:<表>.<列>"`，类型、可空、默认三格各带 `data-k="type"` / `"nullable"` / `"default"`，格子里的文字就是模型里的值（可空写「是」或「否」，没有默认值的格子为空）；字段行里键、引用、来源注释三格带 `data-k="key"` / `"ref"` / `"comment"`；每个说明区带 `data-note="<锚点>"` 与 `data-state`（`none` / `draft` / `reviewed` / `stale`），说明的正文带 `data-k="note"`；表级约束、索引、谁在写、谁在读四张表的每一行各带 `data-row="constraint"` / `"index"` / `"writer"` / `"reader"`。核对器只认这些标记，不认样式类名。

**确定性**：同样的来源与配置，两次生成的整个目录逐字节相同。页面里不写生成时间、机器名、绝对路径。

**原子落盘**（临时目录叫 `docs/.readable-tmp-<进程号>`，替换时旧的先挪到 `docs/.readable-old-<进程号>`；落盘这一步归 render 模块，入口只调用它；出页面的函数本身只返回「路径 → 内容」，不碰磁盘，核对器要拿它在内存里重出一遍来比）：先写到与 `docs/readable/` 同级的临时目录，全部写完再替换；任何一步失败，临时目录删掉，原有的 `docs/readable/` 一个字节不动，退出码 3。测试注入点：环境变量 `READABLE_FAIL_AT=render`，在写完一半页面时模拟失败。

**不带出去的东西**：页面里不出现绝对路径；配置与来源里若有形如内网地址（`10.x.x.x`、`172.16–31.x.x`、`192.168.x.x`）或密钥的字样，第一期原样照出并在 `db/index.html` 顶上列一条警告，是否隐去待用户裁定。

## F. 谁写谁读、代码里建的表、项目判断（Task 1.3）

**扫哪些文件**：`codeRoots` 下的 `.py`，以及 `.ts` / `.tsx` / `.js` / `.jsx` / `.mjs`，去掉 `ignore` 命中的。

**只看字符串里的 SQL**：先把源码切成字符串字面量与其它，只在字面量里找。Python 认单引号、双引号、三引号与 `r` / `b` / `f` / `u` 前缀，`#` 注释不算；JS 一族认单引号、双引号、反引号模板，`//` 与 `/* */` 注释不算。一个文件切到末尾还有没闭合的字符串，整个文件记进「没扫成的文件」，不出半截结果。三种常见写法不许把文件切坏：JSX 标签之间的文字里带撇号（`<p>Don't refresh</p>`）、右括号后面跟正则字面量（`if (s) /'/.test(s)`）、Python f 串的格式说明里带引号（`f"{x:'>10}"`）。只认建表定义里有的表名与视图名（大小写不敏感，可带双引号与模式前缀）；别的名字（临时表、公共表达式、函数）不理。

**认这些写法**：
- 写：`INSERT INTO 表`、`UPDATE 表`、`DELETE FROM 表`、`TRUNCATE [TABLE] 表[, 表…]`、`COPY 表 FROM`、`MERGE INTO 表`。
- 读：`FROM 表`、`JOIN 表`，`FROM` 后面逗号连着的几张表都算。`DELETE FROM` 与 `COPY 表 FROM` 里的 `FROM` 不算读。
- 接口调用：`copy_records_to_table(`、`copy_to_table(` 后面第一个实参是字符串字面量的，算对那张表的写；`copy_from_table(` 算读。conflation 有 11 处写表走的是这个接口，没有 SQL 文本。
- 动词全大写的照认。不是全大写的（小写、大小写混写）要后面像 SQL 才算：表名（可带别名）之后是语句的下一个关键字（`SET`、`WHERE`、`VALUES`、`SELECT`、`JOIN`、`ON`、`GROUP`、`ORDER`、`RETURNING` 这一类）、括号、分号，或者字面量到此结束。逗号只在读的表清单里算（`from a, b where …`），而且逗号后面还得是名字、再接上面这些；写的动词后面跟逗号不像 SQL。不像的不算进谁写谁读，记进「提到了表名、像 SQL 又不像的」清单 `ambiguous`（文件、行、动作、表、那一段的前 80 个字符）——日志和报错里的「failed to delete from orders, will retry」不是在删表，但也不许悄悄丢掉，万一是一种没见过的写法。
- 每处记：文件、行（动词所在的行）、动作（insert / update / delete / truncate / copy / merge / select）、表。`ON CONFLICT … DO UPDATE SET` 里 `UPDATE` 后面不是表名，自然不记。

**表名是运行时拼的**：动词后面跟的是占位（`{…}`、`${…}`、`%s`、`%(名)s`），或者字面量到动词就结束了（后面是拼接），或者上面三个接口的第一个实参不是字面量——记进「表名是运行时拼的」：文件、行、动作、那一段的前 80 个字符。conflation 有 18 处，如 `f"SELECT count(*) FROM {table} WHERE …"`。

**代码里建的表**：字面量里出现 `CREATE TABLE`（带 `TEMP` / `TEMPORARY` 的不算）的，记进「代码里建的表」：文件、行、表名。配置的 `ddl` 可以列代码文件——列了的，把那个文件的字面量切成语句，只把以 `CREATE TABLE` / `ALTER TABLE` / `CREATE [UNIQUE] INDEX` 开头的语句交给建表定义的取事实器（排在所有 `.sql` 之后，按 `ddl` 里的顺序；说明文字里顺口提到这几个词的不算，否则「未解析的语句」里平添噪声），取出的表并进表清单、出处写那个代码文件与行，取不出的进「未解析的语句」；并进去的不再出现在「代码里建的表」。conflation 有两张主库的表只在代码里建，不列出来文档就少两张表。

**同名的别处的表**：一个不在 `ddl` 里的文件自己建了某张同名的表（比如工具脚本往本地 sqlite 里建一张与主库同名的表），它对这个名字的读写照记，但带上标记「这个文件里另有同名的建表语句」——它读写的多半不是主库那张。

**项目判断** `docs/readable-src/map.json`（可以没有；人和 AI 直接编辑，生成器只读、只校验）：

```json
{
  "version": 1,
  "tableGroups": [
    { "id": "order", "title": "订单与明细", "tables": ["orders", "order_items"], "status": "proposed" }
  ],
  "dynamicTables": [
    { "file": "app/api/report.py", "reads": ["orders", "refunds"], "writes": [], "status": "proposed" }
  ]
}
```

- `status` 是 `proposed`（AI 提议）或 `confirmed`（人已确认），页面上照此标档位。`confirmed` 只由人改，AI 只许写 `proposed`。
- 有 `tableGroups` 时按它分组，组页标题用 `title`，组内超过 12 张表照旧切页；没被任何组收进去的表进「未分组」。没有 `tableGroups` 时照 C 节按表名前缀分。
- `dynamicTables` 把一个文件里运行时拼的表名归到具体的表上：这些表的页面上列出该文件，标「项目判断」加档位；「表名是运行时拼的」清单里该文件的条目标「已归属」。
- 对不上的不拦生成，记进「项目判断里对不上的」：组里点到不存在的表、一张表进了两个组（先出现的算数）、`dynamicTables` 点到不存在的文件或表、`status` 不是那两个值之一。

**页面**：
- 表页从上到下：未合并的提示 → 表名、出处、所在的组、服务的需求 → 说明 → 来源里的注释 → 小关系图 → 字段 → 谁在写 → 谁在读 → 表级约束 → 索引 → 建表之后的改动。读者最先要知道这张表是干什么的，结构细节往后放。
- 组页与清单上，组名后面标档位「项目判断 · AI 提议」或「项目判断 · 人已确认」；按前缀分出来的组不标。组页的文件名是 `g-<组 id>.html`，切页的接 `-1`、`-2`。
- 表页加「谁在写这张表」「谁在读这张表」两节：一个文件一行——路径、动作、处数，按引用处数从多到少排，超过 20 个文件的其余收进一个可展开的区。来历标「取自来源（代码里的 SQL）」；由项目判断补的标「项目判断 · AI 提议」或「项目判断 · 人已确认」。一个文件都没有时写明「没有找到写（读）这张表的代码」，全项目还有没归属的运行时表名时补一句「另有 N 处表名是运行时拼的，见清单」，有没扫成的文件时再补一句「另有 N 个文件没扫成，见清单」——否则读者会以为真的没人写这张表。
- 表页加一张小关系图：这张表居中，加上它引用的和引用它的表，最多 12 张，多的在图下用文字列出。
- 表页加一行「服务的需求：未关联——需求一侧的关联在后面的阶段接上」。连不上的要明说，不留空白。
- **代码文件的行号不上页面**（文档模型与 `--facts-json` 里照旧有）：谁在写、谁在读，以及「表名是运行时拼的」「提到了表名、像 SQL 又不像的」「代码里建的表」三张清单，都只写文件，不写行号。代码一改行号就挪，页面跟着变，却没有任何读者在意的变化——页面是入库的生成物，每次提交都带一批只是行号变了的差异，仓库白白变大。建表定义文件（`.sql`）的行号照旧显示；`ddl` 里列的代码文件，它里面那些定义的出处只写文件、不写行号；「没扫成的文件」那张清单里每个文件的原因、`ddl` 里列的代码文件切不出语句时进「未解析的语句」的那句原因，也都不带行号（写「有一处<什么>没有闭合，整个文件没扫」）——它们同样是代码文件（2026-11-23 第三期审查实测：全部代码文件顶上各加三行，有两张表页跟着变）。
- `db/index.html` 加五张清单：「表名是运行时拼的」「提到了表名、像 SQL 又不像的」「代码里建的表」「项目判断里对不上的」「没扫成的文件」，空的不显示。
- `db/index.html` 在分组清单前面放一张分组关系图：一个方框一个组，写组名与表数，点方框到那一组；两个组之间有外键的画一条线，线上写条数，箭头指向被引用的那一组。组超过 20 个就不画，只留清单。被超过一半的组引用的那一组是枢纽（14 个组里要有 8 个以上引用它）：指向它的线不画，在图下用一句话写明哪些组引用了它、各几条——几乎每个组都连着它，画出来只是一团线，看不出别的组之间怎么连。接手的人先要看到整个库分成哪几块、块与块怎么连。

**分组在文档模型里只有一份** `groups`：`[{"id","title","status","tables":[…]}]`，组内按表名排序。有 `tableGroups` 时照它（`status` 取它写的），组的先后也照它写的先后——那是写的人排的阅读顺序——没被收进去的表进 id 为 `_ungrouped`、标题「未分组」的一组，放最后；没有时按 C 节的前缀规则分，按 id 排序，`status` 是 `default`，标题就是前缀，「其它」的 id 是 `_other`，放最后。页面怎么切页是页面的事，组的成员以这里为准，说明也按这里的组挂。

**`build --facts-json`** 多出：`groups`、`usage`（`{"<表>":{"writes":[{"file","line","verb","sameNameDdl"}],"reads":[{"file","line","sameNameDdl"}]}}`，各按文件、行排序；由项目判断补上的条目多一个 `judged`，值是 `proposed` 或 `confirmed`，`line` 与 `verb` 为 null）、`dynamic`（`[{"file","line","verb","head","assigned"}]`）、`codeTables`（`[{"file","line","name"}]`）、`ambiguous`（`[{"file","line","verb","table","head"}]`）、`unscanned`（`[{"file","reason"}]`）、`mapProblems`（`[{"where","problem"}]`）。

## G. 说明的落盘、指纹与待更新（Task 1.4）

**说明挂在锚点上**，第一期四种：`table:<表>`、`column:<表>.<列>`、`group:<组 id>`、`doc:db`。

**每种说明绑定的来源切片**——切片的内容变了，说明才算过期；切片对规范形算 SHA-256 取前 12 位：
- 表：表名、来源里的表注释、各列的名字与类型（按序）、主键与外键。加一个索引、改一个默认值不让表的说明过期。
- 列：这一列的定义全文（类型、可空、默认、键、引用、CHECK）与来源里的注释。
- 组：组的标题与成员表名（排序后）。
- `doc:db`：各组的 id、标题与成员表名（排序后）。加一张表、删一张表、表挪了组，整库的导读都要有人再看一眼——2026-11-24 在一个合成项目上派实现者加了一张表，导读里写的「全库三张表」已经不对，而原先的切片只有组的 id 与标题，工具不标它过期，是那位实现者自己看出来才改的。靠自觉不算数。

**存放**：`docs/readable-src/notes/table/<表>.md`（这张表与它各列的说明）、`notes/group/<组 id>.md`、`notes/doc/db.md`。只有命令写这个目录。文件格式：

```
## table:orders
<!-- readable-docs: fp=2e7a4f482785 status=draft -->

正文……

## column:orders.customer_id
<!-- readable-docs: fp=9c01d2aa41f0 status=reviewed by=张三 on=2026-11-23 -->

正文……
```

一个文件里表的说明在前，列的说明按列名排序。正文是文字：空行分段，`- ` 开头的连续几行是列表，反引号里的是等宽字，别的原样显示，尖括号一律转义。表说明的第一段是「一句话用途」，清单里拿它当这张表的那一行。

**命令**：
- `note put [--file <文件>]`（不给文件就读标准输入）：输入是若干段 `## <锚点>` 加正文，一次可以交很多段。逐段校验——锚点在现行的文档模型里存在、正文不空、正文里没有内网地址与密钥样式的字样；全部通过才落盘，按当时的来源切片盖指纹，状态记 `draft`；有一段不过，整批不落盘，退出码 2，逐段说明原因。指纹只由命令算，交进来的内容里带着 `<!-- readable-docs: … -->` 的一律拒收。
- `note confirm <锚点…> --by <名字>`，或 `note confirm --all --by <名字>`：把指纹仍对得上的说明记成 `reviewed`，带上名字与当天日期；指纹对不上的不改、列出来，退出码 1。
- `note drop <锚点…>`：删掉这几段说明。
- `pending [--json]`：按表列出要补的——没有说明的表、组与 `doc:db`；既没有来源注释也没有说明的列（外键列不算，它的含义由引用关系给出）；指纹对不上的（带着旧正文）；锚点已经不存在的孤儿说明（带着正文，方便改挂到新锚点上）。`--json` 时每张表附一份上下文：列清单（不截）、表与列的来源注释、它引用谁与谁引用它、写它读它最多的几个文件、所在的组，总量控制在 4KB 左右，超了先截读它的文件。只列清单，退出码恒为 0。`--json` 的形状：`{"summary":{…},"tables":[{"anchor","table","missingTable","missingColumns":[<列的锚点>…],"stale":[{"anchor","text"}],"context":{…},"contextBytes"}],"groups":[{"anchor","id","title","missing","stale","members"}],"doc":{…},"orphans":[{"anchor","text"}]}`；`context` 里是 `table`、`group`、`comment`、`columns`、`references`、`referencedBy`、`changes`、`writers`、`readers`、`files`。

**页面**：
- 表页「说明」区：有说明就显示正文，标「说明 · 草稿」或「说明 · 已抽审（谁，哪天）」；指纹对不上的原文照显，上面加一条「这段说明写于来源的旧版本，机械取出的部分仍是现行的」；没有的写「说明：未写」。
- 字段表的「含义」一栏：来源里的注释与说明各自带标记并排显示；过期的说明在格子里标「待更新」。
- 组页顶上显示组的说明，`db/index.html` 顶上显示 `doc:db` 的说明，规则同上。
- 清单里每张表那一行：有表说明用它的第一段（过期的在这一行也标「待更新」），没有用来源里的表注释，都没有留空。
- 孤儿说明不上任何页面。

**`build --facts-json`** 多出：`notes`（`{"<锚点>":{"text","status","by","on","state"}}`，`status` 是 `draft` / `reviewed`，`by` 与 `on` 没有时为 null，`state` 是 `current` 或 `stale`；只含锚点现存的说明）、`orphanNotes`（`[{"anchor","text"}]`，按锚点排序）。页面与核对器按这个读。

隐去的规则只有一份，在 `.claude/scripts/readable/sensitive.mjs`：`redact(文字)` 返回 `{ text, hits }`（换过的文字与换了几处），`REDACTED` 是那个替换用的记号。`note put` 拒收、页面隐去、核对器比对都用它。

**不带出去的东西**（取代 C 节同名一段里「原样照出」的做法）：页面上显示的每一段取自来源的文字（注释、默认值、约束与索引的原文、视图定义、各张清单里的语句开头）以及说明的正文，凡有内网地址（`10.x.x.x`、`172.16–31.x.x`、`192.168.x.x`）、带口令的地址（`://用户:口令@`，用户名为空的 `://:口令@` 也算；用户名与口令只认连着的 ASCII 可见字符）、`sk-ant-` / `sk-proj-` 开头的串、几种形状固定的令牌（`ghp_` / `gho_` / `ghu_` / `ghs_` / `ghr_` / `github_pat_` 开头的 GitHub 令牌、`AKIA` 加十六位大写字母数字的 AWS 访问键、`AIza` 加三十五位的 Google 接口键、`xoxa-` / `xoxb-` / `xoxp-` / `xoxr-` / `xoxs-` 开头的 Slack 令牌、三段都以点隔开且前两段以 `eyJ` 开头的 JWT、私钥的整块——从 `-----BEGIN … PRIVATE KEY-----` 那一行到 `-----END … PRIVATE KEY-----` 那一行，中间的正文一起换掉；没有 END 那一行的，换到 BEGIN 后面连着的那几行只含字母、数字与 `+ / =` 的为止，不许连带吞掉后面的话。照框架自带的密钥扫描里把握大的那几条，2026-11-23 第三期把文件头说明全文上了页面之后补）、`password` / `passwd` / `secret` / `token` / `api_key` / `密码` / `口令` / `密钥` 后面用 `=`、`:` 或全角的 `：` 接着八位以上的值（只取连着的 ASCII 可见字符，到空白、引号、中文或全角标点为止，值里可以有符号）、并且其中带数字或总长不少于十六位的（「token: refreshes the login session」这种正常的英文说明不算；关键字前后用下划线连着别的词也算，如 `AWS_SECRET_ACCESS_KEY=`、`secret_key=`、`db_password:`），页面上换成「〔已隐去〕」，并在 `db/index.html` 顶上写明隐去了几处、各在哪个文件哪一行。规格把「生成物里不出现密钥、内网地址与账号」定为 P0。页面上凡是取自来源或配置的文字都要过这一遍，函数签名、各张清单里的原因、项目判断的问题描述、配置的标题与路径也在内。逐个字段去隐总会漏字段，所以另有一道兜底：`build` 落盘前的自检把每一页的文字再过一遍规则，有命中就不替换、退出码 3、点名是哪一页。**隐去只换掉口令或地址本身，不许连带吞掉后面的话**：中文里很少有空格，值若取到空白为止，「password=Abc12345，生产环境与测试环境各一套……」会把整句一起换掉，而核对两边换得一样、看不出来（第二期审查实测）。所以值与地址里的用户名、口令都只取连着的 ASCII 可见字符：上面那句只换掉 `Abc12345`，「token:Bearer令牌，有效期 24 小时」一个字都不换（`Bearer` 不够八位），「接口在 http://gw-host:8080，有问题发邮件到 ops@example.com」也不换（冒号后面到 `@` 之间隔着中文）。认不出来的也明说：内网域名、账号名、人名、写成一句话的口令，规则认不出，交出去之前靠人看。人读版需求规格那一份的隐去见第二期契约 C 节。

## E. 测试预算

测试代码不超过有效代码的一半，按风险给：
- 建表定义：`ALTER` 合并进表；字符串与 `$$` 里的分号不切断语句；`DO` 块进「未合并」而不被合并；注释的归属与改动备注；外键与 `ON DELETE`；解析不了的语句进清单而不是让整次失败。
- 页面：每张表一页且地址由表名推出；两次生成逐字节相同；注入失败时原目录不变。

## H. 核对（Task 1.5）

`check [--json]`：逐项比对文档与来源，出一份不一致清单。退出码 0 是清单为空，1 是有不一致。四项：

1. **页面是不是现行的**：重新取事实、连同现在的配置、项目判断与说明在内存里重出一遍，与 `docs/readable/` 逐文件比——缺的页、多的页、内容不同的页各点名。来源、配置、项目判断、说明任何一样改了而没重出，或者有人手改了页面，都在这一项露出来。这一项用得着出页面的函数。
2. **页面上显示的与事实一致**：这一项不许用出页面的任何函数，核对器自带一个最小的页面读取器，按 C 节「机器读得回来」的标记把磁盘上的页面读回来——每张表恰有一页，页里的表锚点与文件名对得上；每个列恰有一行，类型、可空、默认、键、引用、来源注释六格与重新取的事实一致，页面上没有事实里没有的列；表级约束、索引、写它的文件、读它的文件各自的行数与事实一致；每个说明区的状态与侧车一致，正文的文字与侧车的正文一致（空白归一后比）。出页面的代码吞了字、串了行，第 1 项两边错得一样看不出来，靠这一项。键不许只放在属性里：字段表每一行显示的列名（`data-k="name"`）、「谁在写」「谁在读」每一行显示的文件路径（`data-k="file"`），显示的字也要与事实比——原先只拿锚点配行，显示的列名、路径写错了看不出来（2026-11-23 第三期审查在架构页上实测出同一类假绿后补）。
3. **说明**：指纹对不上的、锚点已经不存在的，各算一条不一致。没写说明不算不一致，只在摘要里报数。
4. **指向不存在的东西**：`mapProblems` 的每一条；页面里指向站内别的页面的链接，目标文件不存在的。

未合并的动态定义、未解析的语句、运行时拼的表名不算不一致——文档自己已经明说了——只在摘要里报数。

输出：一条一行「在哪：怎么不一致」，末行「不一致 N 条」；不是现行的页超过 10 张时只列前 10 张并写「另有 N 页」，并提示先重出再核对（建表文件靠前处加一行，后面几十张表的出处行号都会变，清单会很长）；`--json` 时是 `{"ok":true|false,"problems":[{"kind","where","detail"}],"summary":{…}}`，`kind` 取 `stale-page` / `missing-page` / `extra-page` / `fact-mismatch` / `note-stale` / `note-orphan` / `note-mismatch` / `dangling`。

`build` 落盘之前先对临时目录跑第 2 项，再把每一页的文字过一遍隐去规则，任何一样不过就不替换，原有页面不动，退出码 3，并说明哪一页哪一项对不上。测试注入点两个：`READABLE_FAIL_AT=selfcheck` 让自检拿到的事实多出一个列；`READABLE_FAIL_AT=leak` 让新出的某一页带上一段没过隐去的内网地址，自检应当拦下并点名那一页。落盘开头先清掉上一次被杀留下的临时目录；页面目录不在而上一次的旧目录还在时，先把旧目录挪回来。

验证用的两个动作：生成后手改任一页的一个类型格，`check` 退出码 1 并点名那一页那一列；生成后在建表定义里加一个列而不重出，`check` 退出码 1。

## I. 开发流程里的落点

边开发边写，不是开发完再补：改的人当场写一两句，比事后让人重读代码去猜便宜得多，也准得多。落点如下，前三处是 2026-11-23 定的：

1. **提交前自动重出**（`.claude/hooks/pre-commit-check.mjs` 里的一段）：项目根有 `docs/readable-src/config.json` 且装着 `readable-docs.mjs` 时，每次 `git commit` 之前先跑一遍 `build`。
   - 重出之后 `docs/readable/` 下有没暂存的变化（改动的、新增的、删掉的页面）→ 拦下这次提交（退出码 2），说明有几页变了，提示 `git add docs/readable` 之后重提。生成是确定的，暂存后再提交这一段就过。
   - `build` 自己失败（配置错、落盘前自检没过）→ 不拦提交，把原因照原样报出来并写明「人读文档这次没重出，现在与来源不同步」——出文档的毛病不该把所有提交都卡死。
   - 重出之后有待更新或成了孤儿的说明 → 不拦，报数并提示任务验收前补齐。
   - 没有 `docs/readable-src/config.json` 的项目，这一段什么都不做、什么都不说。档位照这个钩子原有的规矩：`advise` 档照跑照报、不拦。
2. **任务验收**（dev-builder 的开发规则）：任务碰了建表定义或读写表的代码，就带着文档一起交——`build`、把因本次改动缺的与过期的说明补齐、`check` 报「不一致 0 条」。说明由改代码的人写；主 Agent 验收时亲跑 `check`。
   - 基线：主 Agent 派单之前先跑一次 `check` 与 `pending`，记下不一致的条数与缺口的几个数。派单之前就有的（升级带来的待更新、存量没写的说明）不算这个 Task 的；验收看两样——`check` 里没有比派单前多出来的，`pending` 的缺口数不比派单前多。没写说明不算不一致，只跑 `check` 看不出「新加的表忘了写说明」，要靠后一样。
3. **Phase 收尾**（dev-builder 的四步走）：有人读文档的项目多跑一次 `check`，不是 0 条先补到 0 条，补不齐的记 CONCERNS。

上面三处是「文档已经在了之后怎么跟上」。要让以后的开发过程自动带着文档，还差「谁来起头」和流程里别的几步（用户 2026-11-24：「你是让后续的，Agent开发过程能正常，自动生成这些文档」；当天盘点，计划、派单规则、审查、发版、状态、升级都没接）：

4. **起头**：需求规格生成之后（交付阶段），或 dev-builder 开工时，项目里没有 `docs/readable-src/config.json` → 主 Agent 跑 `init` 与 `build`，交付的话里带一句给人看的版本在哪。这两步是机械的，不写存量的说明。用户明说不出的不建，记进 progress.md。
5. **配置跟上项目**：`init --suggest`（只读，可带 `--json`）。配置已经在时，照现在的项目把 `init` 的起草重做一遍、与现有配置比，报三样，一个字节都不改：
   - 找到了而 `ddl` 里没列的建表定义文件（找法与 `init` 相同的三类；被配置的 `ignore` 排掉的不算）；
   - 里面一个代码根都没有、却有 3 个以上代码文件的顶层目录（代码文件的认法与 `init` 相同；被 `ignore` 排掉的不算；已经有代码根在它里面的顶层目录不报——那多半是有意只取一部分）；
   - 根目录有 `Product-Spec.md` 而 `spec` 是 null、根目录有 `Architecture-Design.md` 而 `archDocs` 里没有它。这两份同样看 `ignore`：有意不出的那一份，把文件名写进 `ignore` 就不再报——`spec` 写 null 本来就是「不出这一份」的正规写法，不给出口的话每次提交都报一条，照着「填回去」就把用户的决定改了回去（2026-11-24 审查的反例）。
   退出码 0 是没有差别，1 是有差别；配置不在时退出码 2 并提示先 `init`。人读输出一样一行，没有差别时写「配置跟得上项目，没有漏项」；`--json` 时打 `{ "ok": true | false, "missing": { "ddl": ["<路径>", …], "codeRoots": ["<目录>", …], "spec": "<路径>" | null, "archDocs": ["<路径>", …] } }`，各清单排好序。提交前自动重出的那一段，重出之后顺带跑它：有差别只提醒一句（列出漏的），不拦提交。新项目先有需求规格、后有代码，配置是在还没有代码时起草的，没有这一步，建表文件与代码目录出现之后没人把它们填进去，数据库设计与架构设计就一直是空的。
6. **计划**：dev-planner 出的 DEV-PLAN「开发规则」带一行——人读文档跟着 Task 走，Phase 验收含 `check` 报 0 条。
7. **派单与回执**：项目有 `docs/readable-src/` 而 Task 碰了建表定义、读写表的代码或模块的文件、接口、跨模块引用的，派单的 Verification 写上「`build`、补说明、`check` 0 条」；实现者回执的 Verified 带 `check` 的末行。
8. **审查**：code-review 的 Stage 1 多核一项——`check` 是不是 0 条、这次新加的表、列、模块有没有说明、新写的说明抽几段对着改动看讲得对不对。
9. **发版**：主 Agent 回指 `/release-builder` 之前核的几项里加一项：有人读文档的项目 `check` 报 0 条。
10. **状态**：`project-status.mjs` 多报一行「人读文档」——没有配置的报「未初始化」；有的报页数、没写说明的表与模块各几个、待更新与孤儿各几段、`init --suggest` 有没有漏项。取不到（没装生成器、命令出错）时报「读不出」并带原因，不当成 0。`--json` 时同样带上这一项。
11. **升级**：`doctor.sh` 在有配置的项目里跑一次 `check`：有不是现行的页面（生成器升级之后页面的写法变了，或来源改了没重出）就提示「人读文档与来源或当前生成器不同步：跑 `build` 后提交」，只提示、不判红——一个项目的文档没跟上，不该让整份安装自检变红。有待更新的说明也提示一句、带上段数（「人读文档有 N 段说明待更新：`pending` 看清单，照现在的来源重写」）：框架升级改了说明绑定的切片时，升级的项目里会冒出来——2026-11-24 起整库导读的切片带上了表名，写过整库导读的项目升级后它必然待更新一次——重出页面清不掉它，得有人知道。
12. **看页面**：技能要求出完文档亲眼看页面，而「看」不能靠本机恰好装了哪个库——`node .claude/scripts/page-shots.mjs <目录> <页面相对路径…> [--out <目录>] [--width 1280] [--segment 1400] [--json]`，零 npm 依赖，用本机已有的 Chrome / Chromium / Edge 走调试端口，把每一页按 `--segment` 的高度切成一段一段的图（十几屏的长页整张截下来缩成一条，读不了）。
    - 找浏览器：设了环境变量 `CHROME_PATH` 就只用它（不存在即算没有）；没设时依次找 PATH 上的 `google-chrome`、`google-chrome-stable`、`chromium`、`chromium-browser`、`microsoft-edge`，Playwright 装在用户缓存目录里的 Chromium，以及 macOS、Windows 上的标准安装位置。
    - 每一页报一行：页面的高度、切了几段、有没有横向溢出（内容比窗口宽）；图落在 `--out`（默认 `.claude/evidence/page-shots/`），名字是「页面路径把 `/` 换成 `_`」加段号，段号从 1 起（`sub/a.html` 的第一段是 `sub_a.html-1.png`）。`--json` 时打 `{ "engine": "<浏览器路径>", "pages": [{ "page", "height", "segments": ["<图的路径>", …], "overflowX": true | false }] }`。
    - 退出码：0 都截了；2 用法不对、目录不在、点名的页面不在或越出了那个目录；3 本机没有找到浏览器（或这个 node 没有内置的 WebSocket）——stderr 一行「看页面缺席：……未执行不等于看过」，一张图都不出。缺席不许冒充看过。
    - 用法先于浏览器：目录、页面、参数的检查都在找浏览器之前做完，用法不对（2）不被缺席（3）盖住；点名的几页里有一页不对就一张都不截。找到了浏览器而起不来、连不上的也算缺席（3），那句话里带原因。
    - 只读被看的目录：`--out` 落在被看的目录里（含它本身）算用法不对（2）。每一页开截之前先清掉 `--out` 里上一轮同一页留下的段——这一轮段数少了或这一页失败了，旧图不许混进来冒充这一轮看过。
    - 单页导航超过 30 秒、打不开或截到一半出错，算这一页失败：退出码 1，别的页照截；这一页已经写出的段删掉，`--json` 里它的 `height` 与 `overflowX` 是 null、`segments` 是空数组，多一项 `error` 写原因。
    - 不留僵尸：浏览器用临时的用户数据目录，正常结束、出错、Ctrl-C、`kill -TERM` 都连进程带临时目录一起收掉；这个脚本自己被强杀（`kill -9`、外面的超时）时没有机会收，所以起浏览器时多带一条调试管道——管道这一头没了，浏览器自己退（2026-11-24 实测：不带管道的，脚本被强杀后浏览器一直挂着；带的三秒内退出）。
    - 冷启动等得起：起浏览器后等调试端口最长 60 秒，超了才算缺席。装好之后第一次启动要建缓存，慢的机器上不止 20 秒（2026-11-24 CI 实测：同一个提交，一台机器整套 21 秒跑完，另一台第一次启动 20 秒没等到）。脚本在浏览器还没起完时就被强杀的，浏览器要起到读管道那一步才退——本机实测起后 0 到 600 毫秒之间任何时刻强杀都在半秒内退出，冷启动慢的机器上退得晚，不是不退。
    - 临时目录路径长也要起得来：完整版 Chromium 在它的临时目录下建套接字，Linux 上用户数据目录的路径超过 62 个字符就一启动即崩（2026-11-24 实测：62 正常、63 起崩）。系统临时目录的路径长到会越过这条线时，用户数据目录改建在 `/tmp` 下；`/tmp` 用不了的照旧建，起不来时缺席的那句话里点明是路径太长。

13. **下游的文档状态随回流一起报**（用户 2026-11-24「这个持续搞吧」——真实项目上的验证持续做，不靠谁记着去看）：框架仓收下游经验的那条命令 `collect-feedback.sh [--dry-run] <项目…>`，在最后那行统计之前给每个项目多报一行，照参数的顺序：
    - 项目里没有 `.claude/scripts/readable-docs.mjs`：`  人读文档  <项目目录名>：没有生成器（框架太旧）`；有生成器而没有 `docs/readable-src/config.json`：`  人读文档  <项目目录名>：未初始化`。
    - 有配置：`  人读文档  <项目目录名>：N 页，核对不一致 A 条，没写说明的表 B 张、模块 C 个，待更新 D 段、孤儿 E 段，配置漏项 F 处，近 7 天提交前被拦 K 次`。
      - N、B、C、D、E、F 取自那个项目自己装的 `project-status.mjs --json --root <项目>` 的 `readable`（F 是 `suggest.missing` 里 `ddl`、`codeRoots`、`archDocs` 列出的个数之和，`spec` 不是 null 再加 1）；A 取自那个项目自己装的 `readable-docs.mjs check --json --root <项目>` 的 `problems` 的条数。用项目自己装的那一份脚本，不用框架仓的——要看的是那个项目手上的生成器怎么说。
      - K 数那个项目 `.claude/evidence/gate-block.log` 里近 7 天、闸名是 `pre-commit-check`、原因里带「人读文档」的行；没有这个文件算 0。
    - A、D、F 有一个不是 0 的，行首的两个空格换成 `! `——扫回流的人一眼看得出哪个项目的文档没跟上。
    - 只读：不在下游项目里写任何东西。任何一步跑不成（输出不是 JSON、命令起不来、超过 60 秒；`check` 因为有不一致而非零退出不算跑不成），那一行写 `  人读文档  <项目目录名>：取不到（<原因首行>）`，不影响 feedback 的收取、统计行与退出码。`--dry-run` 同样报这一行。不依赖系统里有没有 `timeout` 命令（macOS 没有）。
14. **结构变坏当场提醒**（用户 2026-11-24「文档既代码，文档乱说明代码乱，说明设计不合理，说明架构在腐化，一切都暴露在阳光下，无处躲藏」）：架构首页「结构上看得出的」那几张清单本来就照实列着，但循环依赖从 3 组变成 4 组，没有人会为此去翻页面。提交的那一刻由机器比一次。
    - **取结构**：`readable-docs.mjs structure [--page <架构首页文件>] [--json]`，只读。从一张架构首页里读回五样——循环依赖（一组一条，键是成员模块的 id，带这一组里的文件对数）、越层引用（一对模块一条，带文件对数）、未归属的文件、超过 1000 行的文件、项目判断里对不上的条数；不给 `--page` 时读 `docs/readable/arch/index.html`。读法与核对器读回页面是同一套，不另写一套解析。人读输出一行 `结构：循环依赖 A 组、越层引用 B 处、未归属的文件 C 个、超过 1000 行的文件 D 个、项目判断里对不上的 E 条`（B 是各对的文件对数之和，与 `build` 报数行里的口径相同）；`--json` 打 `{ "cycles": [{ "key": "<成员 id 用空格连>", "pairs": n }, …], "upward": [{ "key": "<从> <到>", "pairs": n }, …], "unassigned": ["<文件>", …], "big": ["<文件>", …], "problems": n }`，各清单排好序。页面不在、是没有读回标记的旧格式、或者项目没出架构设计：退出码 2 并说明原因，不猜。
    - **提交时比**：提交前自动重出的那一段，在这次提交放行的那一回（页面都已暂存、不再拦的那一回），拿上一个提交里的架构首页（`git show HEAD:docs/readable/arch/index.html`）与刚重出的这一张各取一次结构，**比条目不比个数**——这一张里有而上一张里没有的循环依赖（新的一组，或同一组的文件对数变多——存量项目的结构多半不是新出一个环，是在已有的环里越缠越紧）、越层引用（新的一对，或同一对的文件对数变多）、未归属的文件、超过 1000 行的文件，以及对不上的条数变多，逐样提醒，每样最多点名三条、其余给个数。提醒的话以 `人读文档·结构：这次提交多了` 开头，末尾写「是有意的在提交说明里写明原因，不是就先理顺再提交」。只提醒、不拦提交，任何档都一样；提醒记进拦截日志，闸名 `pre-commit-check`，原因以 `[advise] 结构变坏：` 开头——不带「人读文档」四个字，免得被第 13 条数成提交被拦。
    - 条目减少了不报。**没得比**——上一个提交里没有架构首页（第一次出）、是旧格式、项目没出架构设计：不比，一个字不出。**比不成**——取结构的命令崩了、输出不是 JSON、超时：不比，提醒一句「人读文档已重出，但没比成结构（原因首行）——不拦这次提交」，不记拦截日志；坏掉的比较不许悄悄地一直坏下去。两种情形都不影响提交的放行与拦截、原有的提醒。因页面没暂存而被拦下的那一回不比（免得同一次改动提醒两遍、日志记两行）；fast 档页面没暂存而放行的那一回同样不比——页面没进提交，下一次还会拿同一张旧页面来比，同一件事反复提醒就没人理了，等页面进提交的那一回再比，攒着的一起报。
    - **回流里带上**：第 13 条那一行在有配置的情形下末尾接一截 `；结构：循环依赖 A 组、越层引用 B 处、未归属的文件 C 个，近 7 天变坏提醒 J 次`——A、B、C 取自那个项目自己装的 `readable-docs.mjs structure --json --root <项目>`；J 数拦截日志里近 7 天、闸名 `pre-commit-check`、原因以 `[advise] 结构变坏：` 开头的行。那个项目装的生成器没有这条子命令、或者项目没出架构设计（退出码 2）时，这一截整个不出，不算取不到。J 不是 0 的，行首同样标 `! `。
