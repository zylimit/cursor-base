# 人读文档 · 第二期契约：人读版需求规格

需求见 Product-Spec.md（REQ-DOC-004、006、007、011），架构见 Architecture-Design.md（§6 场景 2）。本文件是第二期各 Task 的行为契约，测试的断言只从这里推导。入口、退出码、配置文件与第一期相同（见 phase1-db-contract.md）。

这一份文档与数据库设计不同：它**只是把 Product-Spec.md 换一种排法**，一个字不加、一个字不少。不写 AI 的说明，不改写，不摘要。

## A. 来源

配置 `docs/readable-src/config.json` 的 `spec` 是需求规格的路径（相对项目根）。为 null：不出这份文档，首页不列它，不算错。写了路径而文件不存在：与别的配置路径一样，退出码 2 并点名——多半是路径写错了，悄悄不出比报错更坏。

## B. 切块（Task 2.1）

把 Markdown 切成块，按文件里的先后排成一列。认这几种：

| 块 | 怎么认 | 文字是什么 |
|---|---|---|
| 标题 | 行首 1–6 个 `#` 加空格 | `#` 之后的文字 |
| 列表项 | 行首（可缩进）`-` / `*` / `+` 或「数字加 `.` 或 `)`」加空格；紧跟其后、缩进更深、又不是新列表项的行是它的续行 | 去掉记号后的文字，续行用换行接上；记号的原文（`-`、`3.`、`2)`）另记在 `marker` 里——有序列表的序号是内容，不许丢 |
| 表格行 | 行首（可缩进）是 `|`；紧挨着的几行是同一张表，第二行是分隔行（只有 `|`、`-`、`:`、空格）的，第一行是表头 | 各格的文字，按格分开；分隔行不算块 |
| 引用 | 行首是 `>`，连着的几行是一块 | 去掉 `>` 与其后一个空格的文字，行与行用换行接上 |
| 围栏 | ` ``` ` 或 `~~~` 起止的一段 | 起止行之间的原文，一个字符不动；起始行记号后面若还有字（`text`、`json`，或者一句说明），另记在 `info` 里——那也是来源里的字 |
| 分隔线 | 整行只有三个以上的 `-` 或 `*` | 没有文字 |
| 段落 | 别的非空行，连着的几行是一块 | 原文，行与行用换行接上 |

- 列表项按缩进成树：缩进更深的是上一条更浅的项的子项。子项各是各的块，父项的文字不含子项。
- 行内的记号（`**粗体**`、`` `等宽` ``、`~~删除线~~`）留在文字里，不在这一层解释。尖括号写的占位（`<名称>`）是文字，不是标签。
- 表格格子里转义的竖线（`\|`）是文字里的竖线，不是分格。
- 每块取：种类、起止行、层级、所在的章节路径（它上面各级标题的文字，标题自己不算在内）、文字、锚点、指纹。块按出现的先后编全局序号，从 1 起。种类写成 `heading` / `list` / `table` / `quote` / `fence` / `hr` / `paragraph`。层级：标题是级数；列表项是缩进的列数（制表符算到下一个 4 的倍数）；别的块是 null。表格行的文字是各格用 ` | ` 连起来，按格比用 `cells`。文字里保留行尾空白，算指纹时才去掉；续行与引用行开头的缩进、记号后面的空白算记号，不进文字。只有记号、后面连空格都没有的行（`-`、`1.`）也认成空的列表项。
- 锚点按序取第一种能用的：文字开头是 `[REQ-…]` 这种编号的，`req:<编号>`；列表项开头是粗体词的，`spec:<章节路径>/<粗体词>`；别的，`spec:<章节路径>#<在本章里的序号>`。同一个锚点出现第二次，后面的接 `~2`、`~3`。
- 指纹与第一期同一个算法，规范形是「种类加文字」（行尾空白去掉、换行统一）。
- 切块不许丢字：把所有块的文字连同它们被去掉的结构记号按原位放回去，要能逐行还原出原文件（空行的多少不计）。这一条有一个自检函数，取事实时就跑，对不上直接报错退出码 3，不出半份结果。
- **被去掉的记号里不许有字**：算作记号的只能是 `#`、`-`、`*`、`+`、`>`、`|`、`:`、反引号、`~`、数字加 `.` 或 `)`、空白；记号里出现别的字，同样按丢字处理、退出码 3、点名到行。还原自检只保证「块加记号拼得回原文」，字要是被归进了记号，拼得回去页面上却没有——围栏起始行后面的说明文字就是这样丢过一次（第二期审查实测）。
- 测试注入点：`READABLE_FAIL_AT=spec-cut` 让切出来的某一块少一个字，还原自检应当拦下（`build`、`check`、`build --facts-json` 都退出码 3、点名到行、不出任何结果）。

下游一个项目的需求规格是 757 行、434KB，最长一行 7397 个字，超过一千字的行有 25 行；328 个列表项分四级缩进，111 行表格，97 行引用，1037 处粗体，1278 处反引号，17 处尖括号占位，8 处内网地址（2026-11-23 实数）。

`build --facts-json` 多出 `spec`：`{"file","blocks":[{"n","kind","line","endLine","level","path":[…],"text","marker"（列表项才有）,"info"（围栏起始行后面有字时才有）,"cells"（表格行才有）,"header"（表头行为 true）,"parent"（列表子项指向父项的序号）,"anchor","fingerprint"}],"sections":[{"title","level","n","blocks"}]}`。没有 `spec` 时这个键是 null。

## C. 页面（Task 2.2）

- `docs/readable/spec/index.html`：规格的名字与来源；一张章节地图（一个方框一章，写章名与条目数，点方框到那一章）；章节清单（每章几块、其中列表项几条、表格几张）。
- `docs/readable/spec/s-<两位序号>.html`：一个二级标题一页，自成一体。一级标题与第一个二级标题之前的内容归 `s-00`。文件名只用序号，不带章名——中文章名转码之后是一长串看不懂的字符。
- `docs/readable/index.html` 的文档清单里多一项「需求规格」。

每一块照来源的先后显示，带 `data-block="<全局序号>"`、`data-anchor` 与 `id`：

- **条目的地址**：`id` 由锚点推出——锚点是 `req:<编号>` 的，`id` 就是那个编号（`s-04.html#REQ-DOC-004`）；别的取「`a-` 加锚点指纹的前 8 位」；同一页里重了的在后面接 `-2`。它不随别处增删条目而变，只要这一条的章节路径与开头的粗体词没改。每一块开头有一个指向自己的链接记号，鼠标移上去才显示、打印时不显示，键盘的 Tab 不停在它上面（`tabindex="-1"`——一页几百个记号，不能让用键盘的人一个个跳过去）；这个记号自己不带字（字由样式补），读回页面时没有它的字。章的页面按章的序号命名，与清单页上写的章号一致；中间插进一章，后面各章的地址会后移——取舍过：序号读得懂、和清单页对得上，条目一级的地址才是要稳的。

- 标题照级数显示，用与来源同级的标签（来源的二级标题就是 `<h2>`）；三级以下的标题在页内有目录。
- **本章条目**：一章里顶层的列表项有 5 条以上开头是粗体词时，在本章目录里把这些粗体词按来源的先后列出来——挂在各自所属的三级标题下面，没有三级标题的直接列——点了跳到那一条。粗体词超过 28 个字的截到 28 个字加「…」。索引里的字取自条目自己，不带 `data-block`；下游那份规格的「功能需求」一章有 32 条顶层条目、123 条列表项，没有它只能从头翻。
- 列表项照树缩进显示。开头是粗体词的，粗体词当作这一条的小标题。有序列表的项把记号原文（`3.`）显示在前面，带 `data-k="marker"`；不许用浏览器自动编的号。
- **长条目分句显示**（列表项、段落、引用里的每一行都算）：一条的文字超过 200 个字时，在句号、分号、问号、感叹号（全角与半角）之后断行，一句一行；括号、引号、反引号里面的不断；半角的点后面紧贴着字的不算句号（`v2.31`、`11.98GB`、文件名里的点）。只是换了显示，文字一个不动。下游那份规格里一条需求动辄几千字不分段，照原样排是一堵墙。
- 表格显示成表格，表头加重；宽表在自己的框里横向滚，1280 宽的窗口下页面本身不出横向滚动条。
- 引用块收进一个可展开的区，标题写「引用（N 行）」加它的第一行；打印时展开。下游那份规格开头有近百行版本注记，都是引用块。为打印另备的那一份带 `data-print-of="<全局序号>"`、不带 `data-block`，每块引用恰好一份。
- 围栏原样等宽显示；起始行后面的字显示在它上面，带 `data-k="info"`。
- 行内的 `**粗体**`、`` `等宽` ``、`~~删除线~~` 排出来；尖括号一律转义。
- 每页顶上写明：本页内容逐块取自哪个文件的第几行到第几行，只是排法不同。
- **步骤图**：一段有序列表（同一层连着三步以上）时，在这段列表前面画一张步骤图——一个方框一步，写序号与这一步的开头（到第一个标点为止，最多 24 个字），箭头从上一步指到下一步。图是多出来的，列表本身照旧完整显示。
- **流程链图**：列表项、段落、引用里的一句话（与分句同一套规则切出来的一句，不管这一条有没有分句显示）在括号、引号、等宽之外用「→」连着三段以上，并且每一段去掉首尾空白与行内记号后不超过 30 个字时，在这句话后面画一条流程链——一个方框一段、写这一段的原文，箭头照先后连，一行排不下就折行。第一段里最后一个冒号之前的话是引子（「链路参考：」、条目开头的小标题），不进方框。有一段超过 30 个字的不画：那是带箭头的叙述，不是流程。表格里的不画。已经画进步骤图的那几步也不再各自画——同一件事不画两遍（下游规格「首次使用」六步，每一步自己又是一条箭头链，两样都画时一屏里一张步骤图加五条链图，内容重复）。下游那份规格里这样写的句子有 86 句。
- **图不许编字**：步骤图、流程链图一律放在带 `data-fig="<它画的那几块的全局序号，逗号隔开>"` 的元素里，不带 `data-block`；方框里的字只能取自它点名的那几块，截断处加「…」，步骤图方框里的序号带 `data-k="marker"`。
- **不带出去的东西**：与第一期同一份规则（`sensitive.mjs`）。来源里的内网地址、带口令的地址、密钥样式的字样，页面上换成「〔已隐去〕」，`spec/index.html` 顶上写明隐去了几处、各在第几行、**换掉了多少个字**。零丢失的比对按隐去后的文字比——所以规则只许换掉口令或地址本身（第一期契约 G 节），换掉的字数写在明处，读者看得出这一行少了多少、能回来源去看。
- 确定性、原子落盘、每页自成一体、能打印，都与第一期相同。

## D. 核对（Task 2.2）

`check` 多查一项——**需求规格一块不少、一字不差**：重新切块，再用核对器自带的页面读取器把 `docs/readable/spec/` 下各页的 `data-block` 读回来，逐块比：

- 来源里的每一块在页面上恰好出现一次（`spec-missing` / `spec-duplicate`）；
- 页面上没有来源里没有的块（`spec-extra`）；
- 先后与来源一致（`spec-order`）；
- 文字相同（`spec-mismatch`）：两边都把连续空白压成一个空格、行内记号去掉、过一遍隐去规则之后比；表格行按格比；有序列表的项连序号一起比；围栏起始行后面的字（`info`）一起比；引用为打印另备的那一份也比，缺了、多了、字不同都报。
- 结构相同（`spec-structure`）：列表子项在页面上挂在来源里它的父项下面（按页面上元素的嵌套读，不信出页面的代码写的任何属性）；标题的标签级数与来源的级数相同。出页面时把列表的树拍平、把标题全排成一个级别，字一个没少，层次却没了——这一项看的就是它。

- 图里的字取自来源（`spec-figure`）：读回页面时 `data-fig` 的整个元素跳过，不算进任何块的文字；另把它里面每个方框的字（序号除外，去掉末尾表示截断的「…」）拿去比——必须是它点名的那几块的文字（去记号、压空白、隐去之后）里的一段，点名的块不存在也报。

这一项不许用出页面的任何函数。`build` 落盘前的自检也跑这一项。分句显示、步骤图、可展开的区都不许让这一项报不一致——步骤图里的字不带 `data-block`。测试注入点：`READABLE_FAIL_AT=spec-render` 让出页面的代码把某一条列表项的最后一个字丢掉，`build` 应当退出码 3、原有页面一个字节不动。

块数很多、两边差得又多时（两边块数之积超过四百万），不再求最长公共子序列，改成按位置一一配：第几块对第几块，字不同的报 `spec-mismatch`，多出来或缺的照报，不报 `spec-order`。

验证用的动作：生成后把某页里某一块的一个字改掉，`check` 退出码 1 并点名那一块在来源的第几行；从来源里删一条、不重出，`check` 退出码 1。

## E. 测试预算

测试代码不超过有效代码的一半，按风险给：

- 切块：四级缩进的列表成树、续行归上一项；表格里转义的竖线不分格；尖括号占位是文字；引用连成一块；围栏里的 `#` 与 `-` 不被当成标题和列表；还原自检——故意在夹具里放容易丢字的写法（行尾空格、制表符缩进、只有记号没有文字的空列表项、中文与英文标点混排的长行）。
- 页面与核对：每块恰有一个 `data-block`；手改一个字报 `spec-mismatch` 并点到行；删一块报 `spec-missing`；一条 300 字的长条目分句显示之后核对仍是 0 条；内网地址在页面上搜不到而核对仍是 0 条；两次生成逐字节相同。
- 图与索引：四段的箭头链画出四个方框、有一段超长的不画、括号里的箭头不分段；图里的字改掉一个 `check` 报 `spec-figure`；不在标题下面的三步有序列表也有步骤图；条目的 `id` 在前面插一条之后不变；本章条目的链接都指得到。
- 守卫：口令后面的中文不被连带隐去；两个注入点各自让 `build` 退出码 3；把页面上的子项挪到顶层、把标题换一个级别、改掉打印那一份里的一个字，`check` 各自点名。
